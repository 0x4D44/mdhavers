## Notes on what the remaining misses likely represent

This repo has a lot of coverage-only work already; the remaining region misses tend to be in categories that are expensive (or undesirable) to force:

1. **Error propagation branches**
   - Many regions come from `Result`/`Option` handling (`?`, `ok_or`, `compile_ok_or`).
   - In many cases, the “Err” side exists for correctness but is not something we *want* to trigger broadly (e.g., builder failures, IO failures).

2. **Backend-specific branches**
   - `src/llvm/codegen.rs` is very large; even a small percentage gap is hundreds of regions.
   - Some compilation branches are sensitive to inferred types / “fast path” eligibility.

3. **Runtime edge cases**
   - `src/interpreter.rs` still has a moderate region tail; many branches here are likely error-only or integration edges.

## How to drill down (repeatable workflow)

1. Generate a full export (used for the file table above):
   ```
   cargo llvm-cov report --json --output-path target/llvm-cov-export.json
   ```
2. Generate an HTML report with missing lines for interactive triage:
   ```
   cargo llvm-cov --no-default-features --features cli,llvm,native --html --show-missing-lines
   ```
3. Prefer addressing misses that correspond to *real, stable* behavior:
   - deterministic unit/integration tests
   - coverage-only tests under `#![cfg(coverage)]` for pure “hit the branch” exercises
   - small refactors removing unreachable branches (only when invariants truly guarantee unreachable)
