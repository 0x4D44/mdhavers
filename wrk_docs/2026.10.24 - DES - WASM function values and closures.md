# WASM backend: function values, closures, higher-order builtins and pipes

**Date:** 2026-10-24
**Scope:** `src/wasm_compiler.rs`, `src/wasm_runner.rs` only. No interpreter or other backend change.
**Spec:** the interpreter (reference semantics) and DEC F3 (fresh loop binding per iteration).

## 1. Goal

Make these work in the WASM backend:

- a top-level `dae` used as a value (`ken f = greet`, `gaun(xs, helper)`);
- lambdas `|x| ...` (expression or `{ ... }` body) that capture enclosing variables;
- a `dae` nested in a function body (a named closure, recursion included);
- calling any function value (`f(x)`, `make_adder(5)(3)`, `d.f(4)` on a dict field);
- the higher-order builtins `gaun sieve tumble ilk hunt ony aw grup_up pairt_by`;
- pipes `x |> f`;
- builtins used as values (`x |> upper`, `ken len = ...` shadowing a builtin).

Out of scope: classes, top-level variables read inside a top-level `dae` (an existing,
separate restriction), anonymous `dae(...)` expressions (DEC: not in the language), block
expressions other than a lambda's body.

## 2. Representation

A function value is a **host-store object**, like every other value:

```
HostValue::Function { index: u32, arity: usize, env: Handle, name: String }
HostValue::Builtin(String)          // an interpreter builtin used as a value
HostValue::Cell(Handle)             // a captured, shared, mutable variable
```

- `index` is a slot in one guest `funcref` table, exported as `__mdh_fns`.
- `env` is a host list of cell handles (nil when nothing is captured).
- Every table entry has the uniform shape `(func (param $env i64) (param i64 x arity) (result i64))`.
  A lambda or nested `dae` is compiled to such a function directly. A top-level `dae`
  used as a value gets a thin wrapper `$name$v` that drops `$env` and calls `$name`.

The guest makes a value with `__mdh_make_fn(index, arity, env, name_ptr, name_len)` and a
builtin value with `__mdh_make_builtin(name_ptr, name_len)`.

**Why host-side, not a guest-side table of closures.** Every other value already lives in
the host store, so the reclamation scheme, printing (`<dae name>`), equality (identity),
dict/list membership and the builtin bridge all work without a second representation.
A guest-side record would need its own memory manager in linear memory.

## 3. Capture semantics

The interpreter captures the whole defining environment by reference, so closures and
their creator **share** variables: a mutation on either side is visible to the other
(golden `closure_capture_sees_mutations`). The WASM backend models this with **cells**
(closure conversion with boxed captured variables):

1. **Analysis (compile time).** For each lambda/nested `dae`, its free names are the
   names it reads or assigns (including those of lambdas nested in it) minus its
   parameters and the names it declares. A function's *cell names* are
   (a) its own locals/parameters that are free in a lambda it contains, plus
   (b) for a lambda, its own free names (they arrive as cells in `env`).
2. **A cell name's local holds a cell handle**, never the value.
   - read `x` -> `__mdh_cell_get(x)`;
   - `x = v` -> `__mdh_cell_set(x, v)` (returns `v`);
   - `ken x = v` -> `x = __mdh_cell_new(v)`: every execution of a `ken` makes a **fresh**
     cell, so a `ken` in a loop body is fresh each time round, as in the interpreter;
   - a `fer` variable that is a cell gets `__mdh_cell_new(item)` on **every iteration**
     (DEC F3: closures capture that iteration's binding, and see later writes to it in
     the same iteration);
   - a captured parameter, `catch` name or `keek` binding is boxed where it is bound.
3. **Closure creation** builds `env` as a list of the creator's cells (in the lambda's
   free-name order) and calls `__mdh_make_fn`. The lambda's prologue unpacks `env` into
   locals, so inside it those names are cell names too. Nested lambdas pass cells along.
4. **Nested `dae name(...)`** is `ken name = <closure>`. When the body is recursive (the
   name is free in it), the cell for `name` is made first and set after the closure is
   built, so the closure sees itself.

Known divergence (accepted, documented): a second `ken x` of the same name in the same
interpreter scope rebinds in place, so closures made before it see the new value; here
it makes a fresh cell. Block shadowing already diverges in this backend (all locals are
function-wide), so this adds no new class of mismatch.

**Name resolution for non-locals.** A name that is not a local/param/cell is resolved
statically: a top-level `dae` -> a fresh function value; a builtin -> a builtin value;
otherwise the existing validator errors stand. A local that shadows a top-level `dae`
or a builtin name (`ken len = ...`) is initialised at function entry with that dae or
builtin value, matching the interpreter, where the name resolves to the global until the
`ken` rebinds it.

## 4. Call path

All value calls go through one host import per argument count,
`__mdh_callN(f, a1..aN, line) -> i64`. The host dispatches on `f`:

| `f` | action |
|---|---|
| `Function` | check arity (interpreter `WrongArity` message), fetch `__mdh_fns[index]`, call it with `[env, a1..aN]` (re-entrant) |
| `Builtin` | run the interpreter native through the existing bridge, or a host HOF |
| `NativeCtor` / tri | the existing `tri` constructor path (was `__mdh_method_callN(f, "call", ..)`) |
| anything else | `NotCallable` (Scots message from `HaversError`) |

**Why not guest-side `call_indirect`.** A local can hold a function, a builtin or a `tri`
constructor, and the host already dispatches the latter two. Routing every value call
through the host gives one path for guest calls and for the HOF callbacks, with one arity
check. A guest `call_indirect` fast path (check `Function` + arity in the host, then
`call_indirect (type $fnN)`) is a later optimisation; the uniform signature above already
allows it. Direct calls of top-level `dae`s (the hot path) stay plain `call`.

A property call `d.f(4)` keeps `__mdh_method_callN`; when the receiver is a dict and the
key holds a function value, the host calls it like `__mdh_callN`.

A pipe `x |> f` is `f(x)` through the same path (`f` evaluated after `x`, as in
`eval_pipe`).

## 5. Higher-order builtins: host-side, re-entrant

The nine HOFs are implemented in the host (`wasm_runner.rs`), mirroring
`Interpreter::call_builtin_hof` (same list-only argument check, same results). The guest
calls `gaun(xs, f)` as a value call on the builtin value `gaun` (`__mdh_callN`, so errors
carry the line); the host recognises the name and calls the callback with the same
re-entrant routine. A program with a `hae_a_bash` anywhere, closures included, gets the
pending-error checks after every fallible call.

Re-implementing them guest-side would mean emitting a WAT loop per HOF and per call site,
duplicating the interpreter's semantics in a second language, for no reclamation benefit.

### 5.1 Re-entrancy vs reclamation (the key risk)

The invariant (MDH-BUG-FLU-00092): at a scope exit the roots are the current frame's
locals; older frames hold only handles born before the closed scopes opened.
During a HOF the host holds handles in Rust locals (the snapshot of the input list, the
results so far, the accumulator) while guest code runs. These are safe:

- **Host-held handles are older than every callback scope.** Each callback's scopes are
  pushed on top of the caller's open statement scope and fully popped before it returns
  (normal return closes `scope_depth` scopes; the value comes back via the `TMP_RET`
  root). A result is born inside the callback's region, survives its sweep because it is
  a root at `gie`, and then sits young in the *caller's* statement scope, which cannot
  close while the host is still running. The next callback's scopes have a later mark,
  so its sweeps never look at earlier results.
- **Loop in-place sweeps** (`scope_collect`) only sweep the innermost scope's region,
  which belongs to the callback.
- **The closure and its env** are on the caller's operand stack or in a local; they are
  older than the callback scopes. The callback's `$env` parameter is spilled as a root.
- **Writes to shared state** (cells, outer lists) go through `get_mut`, so an older cell or
  container that takes a young value is remembered by the callback's innermost scope and
  promoted to the parent on exit (existing barrier).
- **The root spill area** at the top of memory is shared by all frames, but it is only
  live between a spill and the host call that reads it, which never spans a re-entry.

### 5.2 Re-entrancy vs try/catch

- An error inside a callback, with a `hae_a_bash` open anywhere, is left pending; the
  callback unwinds by `return 0`, leaving its scopes open. The host checks `pending`
  after **every** callback and stops at once, returning nil; the guest's existing check
  after the builtin call branches to its catch (or returns further), and
  `__mdh_try_catch` closes every scope above the try's recorded depth, the callback's
  included. Handles the host still held are garbage by then.
- With no `hae_a_bash` open, the error traps; the trap propagates out of `Func::call`
  and the host returns it unchanged (the runtime error message is already recorded).
- A `hae_a_bash` inside the callback records and pops its own frames; it is balanced
  before the callback returns.

### 5.3 Stack depth

Recursion through function values nests host frames between guest frames. Wasmtime's
stack-limit check is stack-pointer based, so deep recursion still ends in a trap, not a
native overflow. Recursion through direct calls of top-level `dae`s is unchanged.

## 6. Reclamation summary

- `push_children`: `Cell(h)` -> `h`; `Function { env }` -> `env`. A closure keeps its
  env list, which keeps its cells, which keep their values.
- Cells and closures in locals are roots like any handle.
- `cell_set` uses `get_mut` (the write barrier).
- A statement that makes a cell or a closure is never "cheap" (it gets its own scope,
  and a loop whose body makes them sweeps at iteration boundaries). Cell names are never
  numeric locals.

## 7. Validation plan

- Golden parity (`tests/wasm_golden_parity.rs`): re-bless the allowlist after each stage
  and record the counts; expected to clear the HOF, lambda, pipe and dae-value goldens
  that do not also need classes or top-level variables in daes.
- New focused tests in `tests/wasm_validity.rs` (each seen to fail before the change):
  closure capture and shared mutation, F3 per-iteration capture, a nested recursive
  `dae`, every HOF, a HOF callback raising inside `hae_a_bash` (error caught, store
  balanced), a callback error with no catch (clean runtime error), store-size guard for
  a loop that makes closures (bounded `peak_store_size`), arity mismatch on a value call.
- Run: `wasm_validity`, `wasm_golden_parity`, every `tests/wasm_*.rs`, `--lib`,
  `golden_tests`, with `--features wasm_runner`.
