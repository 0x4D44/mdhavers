# Coverage Improvement Plan (Post-Hotspot)

Date: 2025-12-29

## Current State

- Canonical totals (from `target/llvm-cov-summary.json`): regions **99.663%**, functions **100%**, instantiations **100%**.
- Hotspot objective achieved: `src/interpreter.rs` missed regions (**179**) are below `src/llvm/codegen.rs` (**180**).

## Guiding Constraints

1. Preserve canonical floors:
   - Functions **100%**
   - Instantiations **100%**
2. Prefer deterministic coverage additions.
3. Avoid process-wide mutations (env vars, CWD) where possible; if required, use minimal scopes and restore immediately.
4. Avoid adding new uncovered closure instantiations in tests (watch for `unwrap_or_else`, `map_err(|...| ...)`, and other unexecuted closures).

## Multi-Stage Plan

### Stage 1 — “Low-risk, high-yield” interpreter gaps

- Target: cold-but-deterministic branches that do not require network access or OS-specific behavior.
- Approach: small unit tests that directly call private helpers / native functions with deliberately chosen arguments.

Deliverables:
- Reduce `src/interpreter.rs` missed regions further (buffer below codegen).
- Keep canonical floors at 100%.

### Stage 2 — Replace process-global mutations with coverage-only overrides

Some remaining uncovered branches are driven by failure modes of process globals (e.g., `std::env::current_dir()` failure, env-var-driven toggles).

- Add `#[cfg(coverage)]` thread-local overrides for:
  - current directory lookup failure simulation
  - other env-var toggles currently exercised via `std::env::set_var`

Deliverables:
- Eliminate fragile tests that mutate global process state.
- Improve determinism and reduce flakiness risk under parallel test execution.

### Stage 3 — TLS / certificate error mapping coverage

- Add tests that feed invalid PEM/PKCS12 blobs into the relevant helper functions (or native entry points) to hit error mapping code paths without needing live sockets.

Deliverables:
- Cover remaining TLS/DTLS config parse/validation branches.

### Stage 4 — Re-audit remaining top missed-region files

- Re-run instantiation-aware text output and identify remaining `| 0|` blocks in the highest-missed files.
- For each: classify as “coverable”, “requires override”, or “intentionally unreachable”.

Deliverables:
- Final prioritized backlog with estimated effort and risk.
