## Improvement strategy (if we keep pushing beyond 98%)

Region coverage is now in “diminishing returns” territory. The remaining misses are mostly defensive branches and backend-heavy code. If the project wants to push to a higher bar (e.g., **99% regions**), use a staged approach to avoid destabilizing core behavior.

### Stage 0 — Lock in the current baseline (done)

- Keep the canonical command as the scoreboard.
- Treat **instantiations 100%** as a regression floor.

### Stage 1 — Highest ROI, low-risk region wins (parser + wasm compiler)

Targets:
- `src/parser.rs` (23 missed regions; was ~80)
- `src/wasm_compiler.rs` (30 missed regions; was ~68)

Approach:
- Add small, deterministic unit tests that exercise:
  - parser error-path branches (unexpected token, missing delimiters, invalid constructs that still parse)
  - wasm compiler statement/expression kinds not currently compiled in tests
- Prefer compile-only tests (no runtime execution) for wasm compiler.

Exit criteria:
- ✅ Achieved: reduced combined missed regions by **~95** (and kept changes deterministic).

### Stage 2 — LLVM “front door” compiler (small file, low %)

Target:
- `src/llvm/compiler.rs` (38 missed regions, ~95.6% file regions)

Approach:
- Add focused tests to hit:
  - error-reporting formatting branches (but avoid TTY-sensitive behavior)
  - argument validation branches
  - any “early return” compilation paths that are currently untested

Exit criteria:
- Bring `src/llvm/compiler.rs` regions closer to the rest of the codebase (>97%).

### Stage 3 — Cool the remaining hotspot: LLVM codegen

Target:
- `src/llvm/codegen.rs` (339 missed regions; formerly the biggest absolute tail)

Approach (pragmatic):
1. Prioritize coverage wins that are “realistic” to keep deterministic:
   - argument-compilation error propagation inside builtin dispatch arms
   - unreachable `Result` error-propagation that can be removed via small infallible helper refactors
2. Use `target/llvm-cov-export.json` to confirm which regions are still large contributors.

Exit criteria:
- ✅ Achieved: reduced missed regions in `src/llvm/codegen.rs` by **358** (697 → 339).
  - Further reduced to **697 → 337** by covering the `strtod` reuse branch in `is_nummer`.
  - Further reduced to **697 → 335** by exercising additional codegen error branches in unit tests.

### Stage 4 — Interpreter tail (only if still needed)

Target:
- `src/interpreter.rs` (301 missed regions)

Approach:
- Prefer unit tests over integration tests when possible.
- Focus on stable logic branches, not OS/network timing behavior.

Exit criteria:
- Reduce missed regions in interpreter without increasing test runtime substantially.

Progress:
- ✅ Reduced interpreter missed regions **364 → 307** by exercising additional `evaluate()` error-propagation
  paths, removing uncovered `let-else { panic! }` regions in the coverage-only native sweep, and adding
  deterministic DTLS + integration error-path coverage.
  - Further reduced to **364 → 301** by deterministically exercising the DTLS keying-material error mapping branch.

## Measuring progress

For each stage:
1. Run the canonical command and record totals.
2. If totals move, update `wrk_docs/2025.12.28 - CC - Coverage Update.md`.
3. Only proceed to the next stage if the current stage is no longer producing safe gains.
