## Stage 1 — Widen the buffer (reduce interpreter first)

Goal: reduce `src/interpreter.rs` missed regions so we can continue cooling `src/llvm/codegen.rs` without violating the ordering invariant.

Steps:

1. Identify interpreter missed-line clusters:
   - `cargo llvm-cov ... report --show-missing-lines` for a quick scan.
   - `llvm-cov show` for region markers when line coverage is already green.
2. Add small, deterministic tests that execute missing interpreter branches:
   - Prefer CLI subprocess tests for “real program” flows (parsing → runtime → stdout/stderr).
   - Use direct interpreter API tests for error shaping and edge-branches.
3. Re-run the canonical summary after each small change and ensure:
   - functions/instantiations remain 100%
   - the ordering invariant still holds

Exit criteria:

- Interpreter missed regions decreases enough to create at least a ~5 region buffer.

## Stage 2 — Continue cooling LLVM codegen (keep it above interpreter)

Goal: cover additional `src/llvm/codegen.rs` missed regions while maintaining ordering.

Candidate targets (choose 1 at a time, measure after each):

- For-loop lowering branches that depend on terminators (`brak`, `haud`, `gie`) within the loop body.
- Narrow “error-propagation” regions (`?`) in builtin compilation paths where the success branch is already well-covered.
- Small construct gaps found via `target/llvm-cov-export-*.json` segment spans.

Exit criteria:

- `src/llvm/codegen.rs` missed regions meaningfully reduced with ordering preserved.
