# mdhavers: architecture and high-level design (as built)

**Date:** 2026-10-23
**Baseline:** `origin/master` at `81af9d0` (last code change Feb 2026)
**Scope:** how the system is built today, what holds and what does not. The companion plan is
`2026.10.23 - PLN - Architecture Improvement and Overnight Plan.md`.
**Evidence:** five subsystem reviews (front end, interpreter, JS/WASM, LLVM and C runtime,
stdlib/tests/infra), plus runs of the reviewers' repros against a full-feature debug build on
macOS arm64 with LLVM 15.0.7. "Confirmed" below means observed in a run. "Inferred" means
code reading only.

---

## 1. What mdhavers is

mdhavers is a dynamically typed scripting language with Scots keywords (`ken`, `gin`, `dae`,
`kin`, `blether`, `gie`, `aye`/`nae`/`naething`) and Scots error messages. Source files are
`.braw`. One Rust crate (`mdhavers` 0.3.0) holds a shared front end and four execution
backends, plus tooling.

| Component | Path | Lines | Role |
|---|---|---:|---|
| Lexer and tokens | `src/lexer.rs`, `src/token.rs` | 1,034 | logos-based tokeniser |
| Parser | `src/parser.rs` | 2,838 | hand-written recursive descent |
| AST | `src/ast.rs` | 1,203 | 20 statement and 24 expression kinds |
| Errors | `src/error.rs` | 1,666 | about 45 `HaversError` variants with Scots messages and suggestions |
| Interpreter | `src/interpreter.rs`, `src/value.rs` | 24,945 + 1,816 | tree-walking evaluator and about 350 builtins; the reference semantics |
| JS compiler | `src/compiler.rs` | 2,505 | AST to JavaScript plus a runtime prelude |
| WAT compiler | `src/wasm_compiler.rs` | 2,767 | AST to WebAssembly text using a host-handle ABI |
| WASM host | `src/wasm_runner.rs` | 1,247 | wasmtime host for the WAT ABI (feature `wasm_runner`) |
| LLVM backend | `src/llvm/` | about 51,000 | AST to LLVM IR to object file, linked to a native exe (feature `llvm`) |
| C runtime | `runtime/mdh_runtime.c/.h`, `runtime/platform/` | about 11,400 | value operations, I/O, sockets and threads for native exes |
| Rust runtime | `runtime/mdh_runtime_rs/` | about 6,100 | JSON, regex, DNS, TLS/DTLS, audio and 3D for native exes |
| Formatter | `src/formatter.rs` | 1,406 | AST pretty-printer (`mdhavers fmt`) |
| CLI | `src/main.rs` | 1,672 | clap: run, repl, trace, compile, wasm, build, check, fmt, tokens, ast |
| LSP | `src/lsp/` | 1,758 | stdio server: diagnostics, hover, completion |
| Media | `src/graphics.rs`, `src/tri.rs`, `src/audio/` | about 4,000 | raylib 2D, a tri 3D stub, audio and MIDI |
| Logging | `src/logging.rs` | 1,252 | levelled, per-target filtered logging |
| Stdlib | `stdlib/*.braw` | 25,909 | 59 pure-mdhavers modules |
| Tests | `tests/`, plus in-file `mod tests` | 104,794 + about 15,000 | about 9,250 `#[test]` functions |

Feature flags: `default = full = cli + native + graphics + audio + llvm`; `full-no-llvm`;
`minimal = cli + native`; optional `dtls`, `wasm_runner` and `graphics3d`. The LLVM backend is
pinned to **LLVM 15** through `inkwell 0.4` with the `llvm15-0` feature.

## 2. System context

```
                 .braw source
                      │
          ┌───────────┴────────────┐
          │  lexer → parser → AST  │   shared front end (src/lexer, parser, ast)
          └───────────┬────────────┘
     ┌──────────┬─────┴──────┬──────────────┬───────────────┐
     ▼          ▼            ▼              ▼               ▼
 Interpreter  JS compiler  WAT compiler   LLVM codegen    Formatter / LSP / check
 (reference)  → .js + node → .wat + host  → .o + cc link  (tooling)
     │                       (wasm_runner)    │
  natives in Rust                          C runtime + Rust runtime (static, embedded)
```

- The **interpreter** defines the language. The other backends are meant to match it, and
  `CLAUDE.md` lists a five-step process for adding a builtin to every backend.
- The **playground** (`playground/`) compiles the *interpreter* to wasm32 with wasm-bindgen.
  It does not run the WAT or JS backends; it only displays the JS.
- The LLVM build path embeds the runtime archives in the `mdhavers` binary (`include_bytes!`).
  `mdhavers build x.braw` then writes them to temp files and links them with the system `cc`.

## 3. Front end

### 3.1 Lexer (`src/lexer.rs`, `src/token.rs`)
- `logos` 0.14 tokens. Newlines are significant tokens. `#` and `//` comments are skipped
  (`token.rs:300`), so **no downstream tool ever sees comments**.
- Lexing stops at the first bad token (`UnkentToken`) and always appends an `Eof`.
- String bodies are captured raw. The parser processes escapes (`parser.rs:1618`).
- Line and column positions are 1-based and counted in chars, via one forward cursor
  (`lexer.rs:26`).
- F-strings are a single token, matched by a regex that **ends at the first inner `"`**
  (`token.rs:181`).

### 3.2 Parser (`src/parser.rs`)
- Hand-written recursive descent. Precedence from low to high: assignment (right-associative),
  pipe `|>`, ternary `gin c than a ither b`, `or`, `an`, equality, comparison, `+ -`,
  `* / %`, unary, postfix (call, `.`, `[i]`, `[a:b:c]`), primary.
- **Ranges (`..`, `..=`) are attached inside `primary`**, not as a binary level
  (`parser.rs:1358`). So `-1..2` means `-(1..2)` and `x + 1..5` means `x + (1..5)`.
  Both are confirmed bugs.
- `{` in expression position is resolved by backtracking: the parser tries a dict, then
  rewinds and parses a block (`parser.rs:1271`). This is exponential on nested inputs
  (confirmed: 26 levels hang the parser).
- F-string holes are re-lexed and re-parsed with a fresh `Parser`. Their positions restart at
  line 1, and trailing tokens are silently dropped.
- There is no depth limit, so deep nesting aborts the process with a stack overflow
  (confirmed), and no error recovery: the first error ends the parse.
- Spans are `{line, column}` start positions only. Several nodes record the wrong token.

### 3.3 AST (`src/ast.rs`)
- `Stmt` has 20 variants: declarations, control flow, effects (print, log, hurl, assert),
  block and expression.
- `Expr` has 24 variants: atoms, operators, access and mutation, constructors and pipe.
- `Pattern` has 4 variants: literal, identifier, wildcard, range.
- `Display` impls double as the formatter's literal printer, which is where the string-escape
  and float bugs come from.

### 3.4 Errors (`src/error.rs`)
- `HaversError` is a `thiserror` enum. Each variant carries a Scots message, and
  `get_error_suggestion` adds hints.
- Only `UnkentToken` carries a column. Several variants are never raised, among them
  `StackOverflow` and `ReturnOutsideFunction`.

## 4. Interpreter (reference semantics)

### 4.1 Layout of `src/interpreter.rs` (24,945 lines)

| Lines | Contents |
|---|---|
| 1–2,040 | sockets, TLS, DTLS, SRTP, DNS, simulated threads and channels, event loop, coverage fault hooks |
| 2,065–2,556 | `Interpreter` struct, tracing, prelude loading |
| 2,556–10,384 | `define_natives`: **one 7,800-line function** registering 346 natives |
| 10,384–12,509 | the evaluator proper (about 2,100 lines) |
| 12,520–12,875 | hand-written JSON parser |
| 12,875–24,945 | 792 unit tests |

### 4.2 Values (`src/value.rs`)
- `Integer(i64)`, `Float(f64)`, `Bool`, `Nil` and `String(String)` are held inline. Strings
  are cloned on every read.
- `List`, `Dict`, `Set`, `Bytes` and `Instance` are `Rc<RefCell<…>>`. Assignment aliases
  them. A `fer` loop iterates over a snapshot.
- `DictValue` is insertion-ordered (a `Vec` plus a `HashMap` index). Removal is O(n).
- Equality is structural for lists, but by identity for dicts and sets. An empty dict is
  truthy, while an empty list, string or set is falsy. These are confirmed inconsistencies.
- `Value::Range` exists but is unused: ranges are built eagerly as full lists.

### 4.3 Environments and control flow
- `Environment` is a `HashMap<String, Value>` plus an `enclosing` link. Lookup walks the
  chain and hashes the name at every level. There is no resolver pass.
- Closures capture the whole defining environment, which forms `Rc` cycles and leaks. A loop
  variable lives in the enclosing scope, so closures created in a loop all see its last value
  (confirmed).
- Control flow travels as `Result<Value, ControlFlow{Return,Break,Continue}>`, separate from
  errors. `hae_a_bash` catches any `HaversError` and binds its *message string*.
- **There is no recursion limit.** Deep recursion, self-referential containers (printing or
  even tracing them) and deep JSON all abort the process with a native stack overflow. None of
  these can be caught (confirmed).

### 4.4 Classes, modules, builtins
- **Classes.** `kin` classes have a method map and single inheritance. `masel` is bound per
  call. Operator overloading uses magic method names. There is no `super`.
- **Modules.** `fetch` resolves paths relative to the file, then the CWD, then `stdlib/`,
  then every ancestor directory, then the executable's directory. Modules export their whole
  environment, are cached by canonical path, and circular imports are detected. The prelude is
  located by path. If it is missing, startup continues without it and with no warning.
- **Builtins.**
  - Natives are `Box<dyn Fn(Vec<Value>) -> Result<Value,String>>`, so they cannot call user
    code.
  - Higher-order builtins are implemented as magic strings (`"__builtin_gaun__"`), and any
    string with that prefix is callable.
  - Two natives reach the interpreter through a thread-local raw pointer.
- **Concurrency is simulated.** `thread_spawn` runs native functions synchronously. Channels
  never block.

### 4.5 Hot-path costs
- Every statement formats its value for tracing *even when tracing is off*. That is O(size)
  work per statement, and it is why a self-referential dict crashes on assignment.
- Every call allocates two environments, takes two global mutex locks for the shadow stack,
  and clones its arguments.

## 5. JavaScript backend (`src/compiler.rs`)
- A single pass emits a runtime prelude (about 101 helpers destructured into module-scope
  `const`s, plus the audio and logging JS), then the program.
- **No value model.** Ints and floats are both JS `number`, and operators map straight to JS.
  `blether` is `console.log`.
- **Consequences (confirmed under Node):**
  - `7/2` gives 3.5.
  - Division by zero gives `Infinity`.
  - Output prints `true`, `null` and `[ 1, 'a' ]` where the interpreter prints `aye`,
    `naething` and `[1, a]`.
  - `[]` is truthy, and `[1]==[1]` is false.
  - Catch binds an `Error` object.
- **Hygiene bugs (confirmed):**
  - Match-pattern strings are emitted unescaped. This allows code injection, and Node printed
    `INJECTED`.
  - JS reserved words used as mdhavers names (`new`, `class`, …) produce syntax errors.
  - User names that collide with a runtime helper (`len`, `max`) make the program fail to load.
  - Re-declaring with `ken` produces a duplicate `let`.
  - The `fer` variable is `const`.
  - A subclass with its own `init` has no `super()` call.
  - `new` is chosen by whether the name is capitalised.
  - F-string backslashes are not escaped.

## 6. WebAssembly backend (`src/wasm_compiler.rs`, `src/wasm_runner.rs`)
- **Value model.** Every value is an opaque `i64` handle into a host-side store, and all
  operations are `env.__mdh_*` imports. Linear memory holds only string-literal data.
- **Subset.** Supported: variables, if, while, functions, return, print, lists and dicts
  (build only), and property calls. Unsupported: `for`, classes, try, match, indexing, ranges,
  lambdas, f-strings, imports other than `tri`, and every core builtin.
- **Invalid output reported as success.** `compile_to_wat` returns `Ok` for programs whose WAT
  is invalid: a functions-only program (exports a missing `$main`), default parameters, unknown
  callees, or a user function named `main`. Non-ASCII literals are mis-encoded.
- **Host semantics.** The host does arithmetic in f64, turns type errors into nil, never frees
  its store, and keeps dicts in hash order. There is no JS host for the core ABI, so compiled
  WAT cannot run in a browser as shipped.

## 7. LLVM native backend (`src/llvm/`, `runtime/`)

### 7.1 Pipeline
1. `CodeGen` lowers the AST to IR (inkwell 0.4, LLVM 15).
2. `module.verify()` runs, then legacy *function* passes only. There is no module pipeline,
   so no inlining.
3. `TargetMachine` writes a `.o`.
4. `mdhavers build` writes the embedded C runtime archive, Rust runtime archive and GC stub
   to temp files and runs `cc obj … -lm -pthread`.

### 7.2 Runtime representation
- `MdhValue = {u8 tag; i64 data}` (16 bytes), passed by value. That matches the SysV and
  AArch64 ABIs but not Win64 (no `byval`/`sret` handling). The Win64 gap is inferred.
- **Strings** are NUL-terminated `char*` with no length.
- **Lists** are `{items,len,cap}`.
- **Dicts and sets** are flat `[count][k,v…]` arrays with linear lookup, and every insert
  copies the whole dict.
- **Closures** are lists `[fnptr, captures…]` with boxed mutable captures.
- **Exceptions** are `setjmp`/`longjmp` on a global, fixed 64-entry `jmp_buf*` stack.
- **Memory is never freed.** `gc_stub.c` maps `GC_malloc` to `malloc`, and codegen also calls
  `malloc` directly, so switching on Boehm GC would be unsafe as things stand.
- The layout is hand-maintained in four places: `types.rs`, `mdh_runtime.h`, the Rust
  runtime, and literal GEP offsets in codegen.

### 7.3 Why `codegen.rs` is 47,737 lines

| Region | Lines | Notes |
|---|---:|---|
| `compile_call`: one match, 572 builtin arms | 11,833 | 119 arms are the same 8-line runtime-call template |
| 99 `inline_*` IR builtins | 12,381 | e.g. `inline_lt/le/gt/ge` are about 237-line near-copies |
| In-file tests | about 6,040 | |
| `declare_libc_functions` plus its struct | about 2,700 | 348 runtime symbols declared by hand |
| Coverage hooks | 1,000+ | fault injection in production paths |

`src/llvm/builtins.rs` (an arity table) and `src/llvm/runtime.rs` are dead code. Each core
operation exists three times (interpreter, inline IR, C) with different semantics.

### 7.4 Correctness hazards (inferred, high confidence; to be confirmed natively)
- **Per-variable "shadow" caches** (`int_shadows`, `list_ptr_shadows`, `string_len_shadows`,
  `string_cap_shadows`) are not invalidated on reassignment. That gives stale lists, writes
  into read-only literals, use-after-free on aliased in-place appends, and segfaults on
  retyped variables.
- **Exceptions:** `gie`/`brak` inside `hae_a_bash` leaves a dangling `jmp_buf`. A try inside
  a loop grows the stack each iteration. Nesting deeper than 64 silently corrupts the handler
  stack, and a `hurl` on one thread can longjmp onto another thread's stack.
- **Integers wrap** where the interpreter raises an overflow error, and `INT64_MIN / -1`
  traps. Lists with capacity 0 never grow (heap overflow).

## 8. Tooling
- **Formatter** (`src/formatter.rs`) prints the AST and overwrites the file in place. Confirmed
  ways it destroys code:
  - deletes all comments and blank lines;
  - writes `ither { ... }` for else-if chains;
  - writes `...` inside lambda blocks;
  - writes `as` instead of `tae`;
  - leaves string escapes unescaped;
  - prints `1.0` as `1`;
  - breaks f-strings.

  Nothing checks that the output re-parses.
- **LSP:**
  - Diagnostics re-parse on every change and report a single error, without columns.
  - Hover and completion come from static tables.
  - Go-to-definition is advertised but returns nothing.
  - Unhandled requests get no response.
  - Hover indexes a `Vec<char>` by byte or UTF-16 column, which panics on non-ASCII lines.
- **REPL:** the `vars` command panics on non-ASCII values (it slices by byte).

## 9. Stdlib
- 59 modules, all written in mdhavers. The "stable-ish" core is ten modules; network, TLS,
  SIP/RTP/SRTP and concurrency are native-only.
- Six duplicate pairs are each half dead: `math`/`maths`, `dates`/`datetime`,
  `scots`/`scots_lang`, `patterns`/`patterns_match` (with swapped `glob_match` argument order),
  `test`/`testing`, `fsm`/`statemachine`.
- 27 modules are never exercised by any test or example. Some call functions the interpreter
  lacks (`has_key`, `slice`, `tae_json`). These are inferred.
- The installer puts the stdlib where the resolver does not look (inferred).

## 10. Tests and quality infrastructure
- About 9,250 tests. 245 golden `.braw` / `.expected` pairs run on the interpreter and on
  LLVM native. 62 golden files carry `SKIP_NATIVE`, many probably stale.
- Backend parity is six JS smoke cases. Nothing assembles or runs generated WAT.
- The coverage regime is a 98% line gate, 100% functions and instantiations, and a "hotspot
  ordering" guardrail. 56 test files compile only under `cfg(coverage)`, and production code
  carries 186+ coverage seams.
- There is no fuzzing, no property tests and no formatter round-trip corpus.
- **The suite has only ever passed in one configuration** (Linux, `full`):
  - On macOS, `native` failed to compile (BSD `sockaddr_in`).
  - Eight tests are gated on `native` but need `dtls`.
  - Audio tests run without the `audio` feature.
  - The LLVM build depended on a stale `OUT_DIR/mdh_runtime.o` that `cc` 1.2 no longer
    produces, and the platform layer was never embedded.

  Fixes for these are in flight on the overnight build branch.

## 11. Cross-cutting assessment

**What is good**
- The language is coherent and fun, and the interpreter's builtin library is broad and mostly
  hardened (checked arithmetic in core operators, RAII state guards, circular-import
  detection).
- The test volume is large, and the golden corpus is a real asset.
- The Scots error UX is distinctive and consistent.

**Structural problems, in order of consequence**
1. **No single source of semantics.** Each operation is implemented three or four times with
   divergent behaviour, and only six JS snippets and a skip-riddled golden run check parity.
2. **Robustness holes in the reference implementation.** User programs can abort the process
   (recursion, cycles, unchecked native maths, RefCell double borrows). These are exactly the
   failures the Scots error system exists to prevent.
3. **Destructive tooling.** `fmt` corrupts files in place, so it is unsafe to run on any real
   program.
4. **Monolithic files.** `codegen.rs` (47.7K lines), `define_natives` (7.8K lines in one
   function) and the 25K-line `interpreter.rs` are shaped by coverage pressure rather than by
   the domain.
5. **Native memory model.** There is no freeing, quadratic dicts, a NUL-terminated string
   ABI, and a setjmp exception model that is unsafe with returns, loops and threads.
6. **Portability debt.** The build is pinned to LLVM 15, and the Makefile and
   `setup-deps.sh` are Linux-only.
