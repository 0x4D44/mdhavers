## What Changed

### 1) Restored the canonical instantiation floor (100%)

Problem: `src/llvm/compiler.rs` introduced **2 unexecuted instantiations** (reported by `--show-instantiations`) after exposing a generic `with_failpoint` helper under `#[cfg(coverage)]`, dropping canonical `instantiations.percent` below 100%.

Fix:

- Replaced the generic `with_failpoint` helper with a non-generic RAII API:
  - `coverage_inject::set_failpoint(FailPoint) -> FailPointGuard`
  - Re-exported as `set_llvm_compiler_failpoint_for_coverage`
- Updated both unit tests and integration tests to use the guard instead of a closure-returning wrapper.

Result: canonical `instantiations.percent` is back to **100%**.

### 2) Reduced DTLS flakiness by removing repeated native-link builds in an integration test

Problem: the coverage-only integration test for LLVM compiler error branches was repeatedly calling `LLVMCompiler::compile_to_native(...)` under multiple failpoints, which is CPU-heavy and appeared to increase DTLS handshake timeouts/flakes under `cargo llvm-cov`.

Fix:

- Refactored native builds so `LLVMCompiler::compile_to_native_with_source(...)` delegates runtime+link work to:
  - `link_native_executable_from_object(...)`
- Added a cheap dependency-instance coverage helper:
  - `link_native_executable_from_object_for_coverage(...)`
- Updated `tests/llvm_compiler_injection_dependency_paths_coverage.rs` to exercise runtime/link failpoints via the helper (instead of repeatedly compiling+linking).

Result: the canonical coverage run completed successfully with DTLS tests passing.
