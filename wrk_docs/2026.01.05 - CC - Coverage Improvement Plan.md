# 2026.01.05 — Coverage Improvement Plan (mdhavers)

## Goals

1. Preserve hard floors:
   - **functions:** 100%
   - **instantiations:** 100%
2. Maintain guardrail ordering:
   - `src/interpreter.rs` uncovered regions `<=` `src/llvm/codegen.rs` uncovered regions
3. Sustain overall coverage **>= 98%** (already met; this plan focuses on hotspot cooling + stability).

## Stage 0 — Baseline & guardrails (always)

- Run:
  - `timeout 2400 bash scripts/coverage_guardrails.sh`
- Save artifacts:
  - `target/llvm-cov-summary.json`
  - (optional hotspot work) `target/llvm-cov-full.json`

Exit criteria:
- Guardrails pass and totals are recorded.

## Stage 1 — Cool the remaining `codegen.rs` hotspot (reachable paths first)

Prioritize covering:

1. **Closure-as-value materialization with captures** (store captured boxes into closure cell).
2. **Nested function defaults evaluated in closure environment** (default expressions referencing captures / early params).
3. **Builtins / special globals that are user-visible** (e.g., compiler-provided test globals).

Approach:
- Add focused tests under `tests/llvm_codegen_missing_lines_coverage.rs` (`cfg(all(feature="llvm", coverage))`).
- When a branch is structurally defensive (IR validity or impossible by construction), add **coverage-only driver hooks** guarded by `#[cfg(coverage)]` rather than changing language semantics.

Exit criteria:
- `src/llvm/codegen.rs` `regions.notcovered` decreases (tracked via `target/llvm-cov-summary.json`).
- No regressions in guardrails.

## Stage 2 — Reduce `interpreter.rs` micro-misses

Approach:
- Identify remaining missed regions in `src/interpreter.rs` (via `llvm-cov-full.json`) and add:
  - small interpreter-level unit tests, or
  - additional golden tests that exercise semantics (preferred).

Exit criteria:
- `src/interpreter.rs` `regions.notcovered` decreases without violating hotspot ordering.

## Stage 3 — Expand exploratory golden programs (core language)

Goal:
- Drive coverage through realistic programs while catching semantic gaps/regressions.

Program themes (increasing complexity):
- closures and higher-order functions (including default params + captures)
- objects/classes + bound methods as values
- match/destructure edge cases
- module imports + aliasing + rebind behavior

Exit criteria:
- New golden tests pass under both interpreter and LLVM/native golden suites.
- Coverage remains >= 98% and guardrails remain satisfied.

## Stage 4 — Stabilization

- Add timeouts to any newly introduced long-running test loops.
- Keep coverage-only tests isolated and clearly named.
- Update `wrk_journals/` with per-change deltas (tests added, hotspot moved, guardrails outcome).
