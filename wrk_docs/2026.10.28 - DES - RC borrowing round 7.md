# DES - RC borrowing round 7 (native backend)

**Date:** 2026-10-28 (revision 3, after Astra's second review)
**Parent:** `2026.10.26 - DES - RC borrowing.md` (R5 and R6). DEC round 6: redesign RC now, and
make it the default once every benchmark is under about 15% RC cost with no loss of safety.
**Scope:** `src/llvm/codegen/rc.rs`; the top-level variable binding in `src/llvm/codegen.rs`;
`src/llvm/ownership.rs`; one runtime entry in `runtime/mdh_runtime.c`; native RC tests.

Every change is behind `MDH_RC=1`, and with it unset the emitted IR is byte-identical to trunk.
The exception is phase 2b (B for RC-off), which lands later as its own phase. Every elision
below applies only in programs that never start a thread, using R5's compile-time test (a
module-wide use of `__mdh_thread_spawn`). Threaded programs keep R6 behaviour.

## 1. Shared facts and the ownership model

**I-own (the R1 discipline).** Compiled code releases only references its own holders took:
- a temp of the statement;
- one of its own owned variable slots;
- a parameter slot it wrote, which it therefore retained in the prologue.

A release in function F therefore never removes a reference held outside F's frame. F can
drop such a reference only by:
- storing into memory that is not one of its own allocas and releasing the old value;
- calling a runtime function that overwrites, removes or frees (`Drops`);
- running code that does either of these.

Enforcement and testing:
- *Enforced:* by construction in `rc.rs`. Every release site is `store_slot*`, a temp scope
  or an epilogue.
- *Tested:* `MDH_RC_NOFREE=1` (aborts on use of a dead object, naming the line) and
  `MDH_RC_REPORT=1` (live counts at exit), over the RC goldens and benchmarks.
- *Not isolable:* I-own is a property of all of codegen, so no single mutant tests it.

**Owning slots.** These hold a reference for as long as they hold the value:
- an unboxed local in R6's sense (`rc_fn_slots`);
- a written parameter;
- an unwritten parameter, since its caller holds the value for the whole call;
- `masel`.

Change C adds **borrowed slots**, which hold no reference. A borrowed slot is never an
owning slot: not as a chain root, not as an R5 `holder_slot`, and not as a member of the
`holders` set or of A's own-holder set (section 4).

**Rooted chain.** Take a value read as `R[i]...[k]`, where R is an *owning* slot. R's
reference keeps the first container alive, that container's reference keeps the next alive,
and so on. While nothing stores into R and no container is mutated destructively, no link
can die. Releases of F's own references cannot break the chain (I-own). The chain must start
at an owning slot. These roots are excluded:
- a temp (`make()[0]`);
- a borrowed slot. Its value is only as safe as *its* root, which may be overwritten earlier
  (section 4's counterexample).

## 2. Change A: effect summaries for calls (closure, closure_fn)

**What.** For each compiled function, compute two facts on the IR in `rc_elide_borrows`. Use
the same caller fixpoint as `rc_global_writers`.
- `writes_globals(F)`: exists today; reused as is.
- `drops_heap(F)`: F, or something it calls, can drop a reference held in heap memory (an
  element, a field or a captured cell). That includes an argument's holder and the holder of
  the closure F was called through. It is set by any of these local facts:
  - a release whose argument cannot be traced, through `extractvalue` and phis, to a fresh
    call result or to a load from one of F's own **owning** allocas. Borrowed C slots never
    count as own allocas; a release traced to one counts as untraceable;
  - a runtime call that is `Drops` and not in the release family. That includes `m`/`s`
    rows, `free`/`realloc` and `__mdh_shared_store`, which is what captured-cell and global
    writes emit at this point;
  - a `RunsCode` call that is not a direct call of a compiled function: indirect calls,
    callback families, unknown externals, `setjmp`.

  Direct calls pass the fact from callee to caller, which also covers recursion, mutual
  recursion and `__mdh_late_call_N`.

Implement the summary as a free function over a `Module` and the set of owning allocas, as
`rc_split_tag_phis` is. Unit tests can then assert the summary on hand-written IR.

**Use.** In `rc_marker_region_safe`, a direct call of compiled F no longer makes a region
unsafe when `!drops_heap(F) && !writes_globals(F)`. The local-`holder_slot` shortcut
("no other code can reach the slot") stays as it is, but only for owning slots (section 4).

Calls through a closure value are already lowered to a switch of direct calls over the known
candidates, plus `__mdh_native_call*`, which is `Drops` when no native object can exist. Each
candidate is scanned on its own, so the keep-alive retain of `fs[r % 10]` goes once every
candidate is clean. In closure_fn the candidates are `__mdh_fn_adder`, `__mdh_fn_run` and
`__lambda_0`.

**Why the called closure is covered.** The callee reads its captures from the closure object
C that the caller borrowed. C dies only if its holder lets go:
- the list: a heap mutation, so `drops_heap`;
- a global: `writes_globals`;
- the caller's owning slot: unreachable from the callee.

**Globals and captured cells.**
- A callee that assigns a global or a captured cell emits `__mdh_shared_store`, so it is in
  `drops_heap`, and for globals also in `writes_globals`. That is correct: the caller may have
  borrowed the old value.
- Reads keep R5's behaviour: borrowed when no writer runs, `__mdh_shared_load` after a spawn.

While top-level variables are globals, some costs cannot be removed:
- every store of a counted value retains it and releases the old one, because any function
  can name the global;
- stores of unknown kind need tag tests at run time;
- LLVM cannot keep a global in a register across code that may write it;
- after a spawn, R3 locks every access.

The measured gap (+102% at top level against +19.8% in a function, for the same code) is
this cost. Change B removes it for variables nothing else can name.

**Invariants and enforcement.**
- (i) A function outside `drops_heap` drops no reference held outside its frame. Checked at
  compile time; relies on I-own.
- (ii) A runtime row with only `b` arguments that is not `Drops` drops nothing. This is
  trusted, not enforced. The new guard test `no_borrowing_row_removes` checks only names: any
  row whose name contains `remove`, `pop`, `set`, `insert`, `clear`, `delete`, `heave`,
  `toss`, `drain`, `swap` or `replace` must have an `m` or `s` argument, or return a copy
  (`Ret::Fresh` with only `b` arguments, such as `__mdh_dict_remove`). It is a lint, not a
  proof of runtime behaviour, like the existing consumption guard.
- (iii) The program never spawns. Checked at compile time; already exists.

**Threads and R3.** With a spawn anywhere, nothing is elided, and an un-elided borrow is R4's
retain. The test is module-wide, so a spawn reached only through a helper still disables A
(tested).

**Ownership table and A1.**
- Summaries trust rows exactly as `rc_call_effect` does.
- A1 (no row consumes its argument) is what lets a `b`/`m`/`s` call leave the argument's own
  reference alone.

**How a mistake shows.** A use after free inside the callee: a NOFREE abort, or wrong output
without NOFREE. Tests go in `tests/llvm_refcount.rs`. Each checks exact output, REPORT live
count 0, and NOFREE.

| # | Program | Rule it isolates |
|---|---|---|
| A-1 | A closure removes itself from the (captured) list it was called through, then uses its capture | `Drops`-call rule |
| A-2 | A closure reassigns the global that holds it, then uses its capture | `writes_globals` |
| A-3 | A callee overwrites `xs[0]` or `o.f` (a plain element or field store, whose old-value release is visible to the summary) while the caller still uses the old value it borrowed | untraceable-release rule |
| A-4 | A two-level call: a clean-looking callee calls a mutator | propagation |
| A-5 | Mutual recursion, with the destructive store in the second function | fixpoint |

Summary assertions are unit tests on hand-written IR: one function with a visible element

Positive IR assertions: closure_fn's `@__mdh_fn_run` loop contains no `__mdh_retain` of the
called element (count retains in the function, as `retains_in` does).

Mutants, each to be seen failing:
- remove the `Drops`-call rule: A-1;
- remove the untraceable-release rule: A-3 and the summary unit test;
- remove propagation: A-4;
- stop the fixpoint after one pass: A-5;
- ignore the thread gate: A-10.

Not isolable: the `RunsCode` rule for unknown externals. No program reaches one with a live
borrow, and the default already treats them as unsafe.

**Expected saving: a target, not a measured result.** The goal is to remove about 30
instructions per counted closure call, taking closure_fn from +40% to around +11-13%. The two
in-function analogues measure +11.1% and +12.9%, but they also change dispatch, so they bound
the target loosely. Top-level closure gains little until B.

**RC-off impact.** None.

## 3. Change B: top-level variables as `main`'s locals

**What.** Bind an eligible top-level variable of the entry module to an entry-block alloca of
`main` rather than an LLVM global. Register it as an ordinary slot (`rc_register_slot`) and
pin it in try/catch exactly as function locals are pinned (`escape_slots_before`). It then
gets R5 borrowed reads, `mem2reg`, the tag split, and no `__mdh_shared_*` calls.

**Eligibility.** A pass over the AST before codegen decides it. A variable is eligible only
when all of these hold:
- The program has **no `fetch`** at all (first version). Imported code compiles with
  `self.globals` still in place, so an imported function, or a module's top-level
  statement, can name an importer's variable. A later version may instead analyse
  visibility over the transitive import graph, keeping one binding for shared and exported
  names.
- The name occurs in no function, lambda, method, constructor or class body, and in no
  **parameter default** of any of them, including defaults on function values. Defaults run
  in the callee's environment, and codegen drops caller locals before compiling them.
- The variable is never boxed (captured).

The check over-approximates: any occurrence of the name counts, whatever shadowing is in
force. Both walks (for `fetch` and for names in bodies and defaults) cover the whole AST,
including declarations nested inside functions, blocks, classes and lambdas.

**Invariant.** Only `main`'s own statements can name the variable. It is enforced at compile
time by the AST pass. Under it, the variable is a local in every sense codegen uses. The REPL
and `trace` use the interpreter, so this change does not touch them.

**Threads and R3.** A thread runs a function. Functions cannot name an eligible variable, so
no other thread can reach the slot. Values may still be shared through containers, as for any
function local, and R3 covers neither. The binding is therefore correct with threads, while
B's borrow elisions remain gated off.

**Ownership table and A1.** No interaction.

**How a mistake shows.** The likely failure is a compile error from an unknown name, or wrong
output from a stale global. Goldens already read top-level variables from functions. New
goldens, each run under RC with exact output:
- B-1: a function reading and assigning a top-level variable.
- B-2: a lambda capturing one.
- B-3: a thread function reading one.
- B-4: a method reading one.
- B-5: a parameter default naming a top-level variable, called with the argument omitted
  before and after the variable is reassigned. One test each for a function, a method, a
  constructor and a function value.
- B-6: a top-level variable used only at the top level, assigned in a `hae_a_bash` body and
  read in `gin_it_gangs_wrang` and after it (checks the pinning).
- B-7: a program with `fetch` whose imported function and module initialisation read an
  importer's variable. This checks the no-`fetch` rule.
- B-8: shared imported bindings reassigned from both sides, a repeated or cached import, and a
  name collision between modules.

Positive IR assertion: in closure.braw, `fs`, `s`, `r` and `f` are allocas of `main`, not
`@__mdh_global_*`.

Mutants, each to be seen failing:
- treat every top-level variable as eligible: B-1 to B-4;
- skip parameter defaults: B-5;
- allow `fetch`: B-7;
- skip the try pinning: B-6.

Not isolable: ignoring shadowing. That over-approximation can only keep more globals.

**Expected saving (estimate).** closure +69% to about +40% (the same program inside a function
measures +40.1%), and to the A target with A. method +12.5% to about +8.6% (measured
in-function analogue). particle_sim is unchanged.

**RC-off impact.** Gated on RC, so RC-off IR stays identical. Lead ruling Q1: apply B to RC-off
later, as its own phase (2b), once RC-on B is validated.

## 4. Change C: borrowed local slots (particle_sim)

**What.** A local slot S becomes a borrowed slot when every store into it is a borrowed read
from a rooted chain, and S is unboxed and not a parameter. It works like R4's unwritten
parameters: S holds no reference, so its stores take no retain, and its overwrites, scope
exits (`brak`, `haud`, `gie`) and epilogue release nothing.

Codegen emits both forms:
- a borrow marker at each store;
- a new release marker, `__mdh_rc_borrow_release`, at each release of S's old value or of S
  at an exit.

`rc_elide_borrows` then decides per slot, all-or-nothing:
- on success, it deletes both markers;
- on failure, it turns them into `__mdh_retain` and `__mdh_release`, which is exactly R6 code.

**The ownership model change (the review's blocker).** A borrowed slot holds no reference, so
it cannot vouch for anything read through it. The counterexample:

```
dae run() {
    ken xs = [[[1]]]
    ken a = xs[0]
    ken p = a[0]
    xs = []
    blether p[0]
}
```

Revision 1 would have let `a` and `p` both become borrowed. Overwriting `xs` frees all three
lists, so `p[0]` reads freed memory. The rules are now:
- **No borrowed root.** C(c) accepts only an owning slot as R (section 1). If S's stored
  value is rooted in another C candidate T, then S fails, and T keeps its own decision.
  The complete candidate set is collected before any decision is made. A slot rooted in any
  candidate is rejected, whether or not that candidate succeeds, and a failed candidate never
  becomes an eligible root later. That keeps the decision acyclic and independent of order.
- **R5 records that name a borrowed slot are downgraded.** Downgraded means `holder_slot =
  None`, so any `RunsCode` and any `Drops` other than re-park makes them unsafe. This
  applies to a `holder_slot`, and to the slot of an `rc_borrowed_read` or `rc_note_write`
  record, once that slot is decided borrowed. The local-slot shortcut at
  `rc_marker_region_safe` (`Some(slot) if !self.rc_is_shared_slot(slot) => false`) must not
  apply to a borrowed slot.
  - An `rc_borrowed_read` record (`rc.rs` `rc_borrowed_read`) is not a marker: today a read
    of an owning local in a statement gets no retain at all unless `rc_note_write` fires. A
    borrowed read of a borrowed slot must therefore be *materialised* when it is downgraded:
    give it the retain, temp park and statement-end release that `rc_note_write` builds,
    emitted as a borrow marker so the downgraded record is then decided by the normal
    holder-`None` rules.
- **The `holders` set, and A's own-allocas set, exclude every C candidate.** A release traced
  to a load from a candidate is untraceable for A. Candidates are excluded even when they
  fail; that is conservative.
- **A store into a candidate is an escape, by an explicit rule.** Removing candidates from
  `holders` is not enough. R5's escape scan treats an alloca that is only loaded and stored
  (`rc_scratch_loads`) as a carrier and follows its loads as further uses, and a candidate
  slot looks exactly like that. The scan must check candidates first and report a store of a
  derived value into one as an escape, except the candidate's own stores, which C decides.
- **Order inside `rc_elide_borrows`:**
  1. compute the summaries (A), with candidates excluded;
  2. decide the C slots;
  3. decide the R5 records, with borrowed slots downgraded.

  Steps 2 and 3 never feed back into step 1.

**S qualifies when all of these hold:**
- (a) The program never spawns, and S is not boxed.
- (b) The function contains no `setjmp` (try/catch) and no `invoke` or `callbr`. A handler
  can load S along the `longjmp` edge, which the scan cannot see.
- (c) Every stored value is a rooted read: a load of an owning slot R (R is not S and not a C
  candidate), then index or field reads, with every phi edge borrowed or `Skip`. In the
  first version, all of S's stores must share one root R. A fresh edge or a second root
  rejects S, and S falls back to R6 code.
- (d) The protected interval starts at **each originating load of R**, not at the store into
  S. It runs through the evaluation of the rest of the initialiser, the store into S, and
  every use of a value loaded from S (and anything derived from it). On every path in that
  interval there is none of the following:
  - a store into R, or a `Drops` call passed R's address;
  - a store into any container element or field, or a `Drops` runtime call other than a
    release. With no alias analysis, a mutation through a second alias (`ys = xs; ys[0] =
    ...`) is caught by this rule;
  - a release not traced to F's owning holders;
  - a `RunsCode` call, unless it is a direct call of F with `!drops_heap && !writes_globals`.

  Starting at the root load matters because an index evaluates its object before its index
  (`compile_index`). In `ken p = xs[(xs = [[0]])[0][0]]` the old `xs` is loaded first, then
  the index expression replaces `xs` and releases the old list, which the statement's temp
  alone then keeps alive. Checking only from the store would miss the store into R. The
  interval also covers values loaded from S before an overwrite of S and used after it: the
  region follows uses of loaded values, not the next store.
- (e) Every value loaded from S follows R5's escape rules. A store into an owning holder, a
  capture or a `gie` takes its own reference, so it is not an escape. A store into another
  borrowed slot is one.

**Kind-aware releases.** The DEC note asks for leaf-kind releases (string, bytes) to be
allowed in regions. The rule is sound, but it does not unblock `pj`. Its region contains slot
stores (`dx`, `dy`, `d2`, `d`, `force`, `ax`, `ay`) whose old values have unknown kind when
the scan runs. Rule (d) covers those releases by ownership instead. Kind-aware releases remain
optional (section 6).

**Invariants and enforcement.**
- Owning root, rooted chain and region: compile time.
- No borrowed root, and the R5 downgrade: compile time, with tests C-9 and C-10.
- I-own: by construction; tested by NOFREE and REPORT.
- (a) and (b): compile time.

**Threads and R3.** Gated off with threads. R3 is not involved: locals are not shared slots.

**Ownership table and A1.**
- (d) treats `m`/`s` rows as destructive, with `__mdh_list_push` the only exception as today,
  and `b` rows as harmless.
- A1 is what lets a `b`/`m`/`s` call on R's container leave that container alive.

**How a mistake shows.** A use after free of an element held by a borrowed slot shows as a
NOFREE abort at the read, or as wrong output. A missed release marker shows as a REPORT leak;
a double release as a NOFREE abort. Tests run inside functions, each with exact output, REPORT
and NOFREE:

## 5. Change D: element reads without a fresh string edge

**What.** Add `__mdh_char_at_interned`, declared and called only when RC is on. Its row is
`("__mdh_char_at_interned", "bb", Ret::Static)`, so `rc_roots` classes the result `Skip`.
The owned part of an index read is then nil on every edge, and the temp, its park and its
release disappear at compile time. This also gives C an all-borrowed-or-`Skip` edge set.

**Semantics.** The function keeps `__mdh_char_at`'s behaviour exactly:
- negative indices count from the end;
- invalid UTF-8 hurls "Invalid UTF-8 in string";
- out-of-range indices raise the same `__mdh_index_oob` error;
- a non-string or non-int argument raises the same type error.

Factor the decoding into one shared helper, so the two entry points cannot drift apart. Every
return path, including the ones after an error call that may return under a handler, returns
a static object (the interned character, or a static empty string), never a fresh one.

**Table.** Full Unicode, as the lead ruled on Q2.
- **Shape:** a two-level table. The top level is a static array of 4352 page pointers
  (34 KiB), one per 256 code points. Pages hold 256 entry pointers (2 KiB) and are allocated
  on first use. That is smaller than the 64K-entry pages of revision 1, which cost 512 KiB
  each, as the review pointed out.
- **Entry:** one `malloc` block, a 16-byte header plus up to 4 UTF-8 bytes and a NUL,
  rounded by the allocator to 32 bytes.
- **Memory cost, documented in the runtime and the language docs:**
  - ASCII text: 1 page plus 128 entries, about 6 KiB;
  - every code point used (the worst case): 4352 pages and 1,114,112 entries, about 8.5 MiB
    plus 34 MiB.

  The memory is never freed: it is static data for the process's lifetime.

**Publication protocol.**
1. Load the page pointer with an acquire load. If it is null, allocate a zeroed page and
   install it with a compare-and-swap (CAS) that has `acq_rel` ordering on success and
   `acquire` on failure (a valid portable C pair; release-success with acquire-failure is
   not). The thread that loses the CAS frees its page, then uses the winner's.
2. Load the entry with an acquire load. If it is non-null, return it.
3. Otherwise build the entry completely before anyone can see it:
   - an immortal header: `IMMORTAL_REFCOUNT`, the string kind, the magic and
     `OBJ_FLAG_IMMORTAL`;
   - then the bytes.

   Allocate it with plain `malloc`, not `__mdh_obj_alloc`, so it never enters RC accounting.
   It is the same kind of object as a static literal.
4. Install it with a CAS from null (`acq_rel` on success, `acquire` on failure). The thread
   that loses frees its entry with `free` (it was never published or counted) and returns the
   winner's.
5. If an allocation fails, free any block allocated in this call and not yet published, then
   call `__mdh_raise_out_of_memory()`: the catchable "ower muckle" error the checked
   allocators already raise. Its error object is static, so raising allocates nothing.
   Already-published pages stay cached. The function never returns a fresh or partly built
   object.

**Invariant.** Every returned object is immortal and fully initialised before any thread can
see it.
- Run time: the immortal header, plus `acq_rel`/`acquire` ordering.
- Retain and release already skip immortal objects.
- The in-place string append reallocates only a buffer the variable itself grew (its capacity
  shadow is 0 for any other string, so the first append copies), as it already does for
  immortal literals.

**Threads and R3.** No lock is needed: publication is by CAS, and entries never change after
it. The first spawn drains nothing.

**Ownership table and A1.** One new row. `Static` means there is no reference to take, so A1
holds trivially.

## 8. Risks, and what would make me stop

- **Summaries too coarse.** If most functions end up in `drops_heap`, A saves less.

- **Hidden edges.** A borrowed slot read on a path the CFG does not show. `setjmp` is the
  known case (C(b)). No generator or yield path exists in native codegen today. Stop if
  another case turns up, such as user code run from signal or exit handlers.

- **Threaded programs pay the full cost.** Phase 6 measures it before the flip.
- **D's memory.** Programs that index many distinct code points keep up to about 43 MiB of

- Stop at any NOFREE abort or REPORT increase that is not understood. Stop at any design fork:
