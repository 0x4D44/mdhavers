# DES - RC borrowing round 7 (native backend)

**Date:** 2026-10-28
**Parent:** `2026.10.26 - DES - RC borrowing.md` (R5 and R6); DEC round 6: redesign RC now, and make
it the default once every benchmark is under about 15% RC cost with no loss of safety.
**Scope:** `src/llvm/codegen/rc.rs`, the top-level variable binding in `src/llvm/codegen.rs`,
`src/llvm/ownership.rs`, one runtime entry in `runtime/mdh_runtime.c`, native RC tests.
Every change is behind `MDH_RC=1`, and with it unset the emitted IR is byte-identical to trunk.
Every elision below applies only in programs that never start a thread (R5's compile-time test:
`__mdh_thread_spawn` is unused). Threaded programs keep R6 behaviour.

## 0. Where the cost is (measured)

Release compiler at d61bfaf (0.3.109), `--no-default-features --features cli,llvm,native`,
-O2. Instructions retired (`/usr/bin/time -l`), min of 3 runs, RC on vs off.

| Benchmark | Off | On | RC cost |
|---|---:|---:|---:|
| closure (top level) | 116.8M | 197.8M | +69.3% |
| closure_fn (same, inside `dae run()`) | 109.2M | 153.0M | +40.1% |
| particle_sim | 1,477.1M | 1,705.4M | +15.4% |
| method (top level) | 504.6M | 567.8M | +12.5% |
| dict | 455.3M | 490.8M | +7.8% |

The other six (fib, intloop, alloc, strbuild, list, expr_eval) are between -9% and +6% (R6 table).

To find the causes I measured variants of these programs, each changing one thing:

| Variant | RC cost | What it shows |
|---|---:|---|
| closure, but `s = s + fs[r % 10](r)` (no `f`), top level | +61.7% | the global `f` is not the main cost |
| closure without closures (list of ints), top level | +102.2% | top-level variables (globals) are the main cost |
| same, inside a function | +19.8% | locals remove about 80% of it |
| closure_fn, but `s = s + fs[r % 10](r)` | +39.7% | in a function the cost is in the call |
| that, with plain functions in the list (not counted) | +11.1% | the counted callee costs about 29 instr per call |
| one closure in a local, `s = s + g(r)` | +12.9% | a local closure is called without a keep-alive |
| `s = s + inc(r)`, direct call | +2.3% | |
| method, inside a function | +8.6% | method too is mostly a top-level cost |
| top level, ints only (`s = s + r`) | +0.6% | int shadows already cover pure-int globals |

particle_sim's inner loop runs 5,300,250 times, and RC adds 228.3M instructions, so about
43 per iteration. Removing `ken pj = particles[j]` (reading `particles[j][k]` directly) cuts
RC's share to 119.0M. Keeping the slot but replacing its three reads `pj[0]`, `pj[1]`,
`pj[4]` with non-reads leaves 73.6M. Reading `pi[0]` and `pi[1]` costs nothing measurable,
because LLVM hoists them out of the inner loop. So, by difference:

- the `pj` slot (retain on store, release of the old value) costs about 74M, about 14 per iteration;
- the three element reads of `pj` cost about 154M, about 10 per read.

The read cost's mechanism is an **inference** from the IR, not a measurement. An index of
a value of unknown kind is a phi of four edges: list element (borrowed), dict value (borrowed),
`__mdh_char_at` (a fresh string) and type error (nil). R5 parks the fresh part
(`rc_owned_part`, nil on the other edges) in a temp. The temp's release at the statement's end
is a run-time tag test that the optimiser cannot thread through the arithmetic in between.
Phase 3 begins by confirming this.

## 1. Two shared facts

**I-own (the R1 discipline).** Compiled code releases only references that its own holders took:
a temp of the statement, its own variable slot, or a parameter slot it wrote (and so retained
in the prologue). A release in function F therefore never removes a reference that a holder
outside F's frame counts on. F can drop such a reference in only three ways:
- a store into memory that is not one of F's own allocas, followed by a release of the old value;
- a runtime call that overwrites, removes or frees (`Drops`);
- running code that does one of these.

*Enforced:* by construction in `rc.rs` (every release site is `store_slot*`, a temp scope,
or an epilogue). *Tested:* `MDH_RC_NOFREE=1` (an extra release makes a later use abort,
naming the line) and `MDH_RC_REPORT=1` (a missing release leaks) over the RC goldens and
benchmarks. No single mutant isolates I-own: it is a property of all of codegen.

**Rooted chain.** A value read as `R[i]...[k]`, where R is an unboxed local, parameter or `masel`
slot, is kept alive by R's reference to the first container, that container's reference to the
next, and so on. While nothing stores into R and no container is mutated destructively, no
link can die. Releases of F's own references cannot break the chain (I-own). The one
exception is a link held only by a temp (`make()[0]`), so a chain must start at a variable
slot, never at a temp.

## 2. Change A: effect summaries for calls (closure, closure_fn)

**What.** Per compiled function, compute two facts on the IR in `rc_elide_borrows`, next to
`rc_global_writers` and by the same caller fixpoint:
- `writes_globals(F)`: exists today, reused as is.
- `drops_heap(F)`: F or something it calls can drop a reference held in heap memory. That
  covers a container element, a field or a captured cell, and also an argument's or
  the called closure's holder. Local facts that set it:
  - a release whose argument cannot be traced (through `extractvalue` and phis) to a load from
    one of F's own holder allocas (`rc_fn_slots`, `rc_temp_pins`) or to a fresh call result;
  - a runtime call that is `Drops` other than the release family (including `m`/`s` rows,
    `free`/`realloc`, `__mdh_shared_store`);
  - a `RunsCode` call other than a direct call of a compiled function (indirect calls,
    callback families, unknown externals, `setjmp`).
  
  Direct calls propagate from callee to caller.

In the region scan (`rc_marker_region_safe`), a direct call of compiled F no longer makes a
region unsafe when `!drops_heap(F) && !writes_globals(F)`. This applies whatever the record's
holder is. A record with a local `holder_slot` is already safe against any code. Calls through
a closure value are already lowered to a switch of direct calls over the known candidates,
plus `__mdh_native_call*` (`Drops` when no native object can exist). Each candidate call is
scanned on its own, so the keep-alive retain of `fs[r % 10]` goes once every candidate is
clean. In closure_fn the candidates are `__mdh_fn_adder`, `__mdh_fn_run` and `__lambda_0`.
Late-bound calls go through `__mdh_late_call_N`, which is itself a compiled function, so its
summary comes from the same fixpoint.

**Why the called closure is covered.** The callee reads its captures from the closure object C
that the caller borrowed. C dies only if its holder lets go: the list (a heap mutation, which
sets `drops_heap`), a global (`writes_globals`), or the caller's own slot (not reachable).

**Globals and captured cells.**
- A callee that assigns a global is in `writes_globals`, as today.
- A callee that assigns a captured variable stores into a cell element (heap memory) and
  releases the old value, so it is in `drops_heap`. That is right: the caller may have
  borrowed the cell's value.
- Reads of either stay as R5 has them: borrowed when no writer runs, `__mdh_shared_load`
  after a spawn.

What is unavoidable while top-level variables are globals:
- Every store of a counted value into a global must retain it and release the old one, since
  any function can name the global.
- A store of a value of unknown kind needs both tag tests at run time.
- LLVM cannot keep a global in a register across code that may write it.
- After a spawn, R3 locks every global access.

The measured gap (+102% at top level against +19.8% in a function, for identical code) is that
cost. Change B removes it for variables that nothing else can name.

**Invariants and enforcement.**
- (i) A function not in `drops_heap` drops no reference held outside its frame. Compile time
  (the IR scan), and it depends on I-own.
- (ii) Every runtime function with a row that is not `Drops` and has only `b` arguments drops
  nothing. Tested by the ownership table tests; see below.
- (iii) Never-threaded program. Compile time, existing.

**Threads and R3.** With a spawn anywhere, nothing is elided, so the lock is unaffected. An
un-elided borrow is the R4 retain, which is correct under threads.

**Ownership table and A1.**
- Summaries trust rows exactly as `rc_call_effect` does today: `m`/`s`, or a `Drops`
  family name, means it may drop; anything else means it drops nothing.
- A1's invariant (no row consumes its argument) is what lets a `b`/`m`/`s` call leave the
  argument's own reference alone.
- New guard test `no_borrowing_row_removes`: rows whose names contain `remove`, `pop`, `set`,
  `insert`, `clear`, `delete`, `heave`, `toss`, `drain`, `swap` or `replace` must have an
  `m` or `s` argument, or be a known copy-returning function (`Ret::Fresh` with only `b`
  arguments, such as `__mdh_dict_remove`).

**How a mistake shows.** A use after free inside the callee, typically a capture of a freed
closure. That is a `MDH_RC_NOFREE` abort, or wrong output (`xy1`-style reuse) without it. New
tests in `tests/llvm_refcount.rs`, each with exact output plus REPORT and NOFREE:
1. A closure that removes itself from the list it was called through (the list is captured,
   so it is a cell), then uses its capture.
2. A closure that reassigns the global holding it, then uses its capture.
3. A closure that writes a captured cell whose old value the caller still uses after the call.
4. A two-level call: the clean-looking callee calls a function that mutates the list.

Mutants, each to be seen failing:
- Drop the `Drops`-call rule from `drops_heap`: test 1 should fail.
- Drop propagation through direct calls: test 4.
- Drop the "release of an untraceable value" rule: test 3, because the cell write's release is
  of a value loaded from the cell.

Not isolable: the `RunsCode` rule for unknown externals. No program reaches an unknown
external with a borrowed value live, and the existing default already makes them unsafe.

**Expected saving (estimate).** About 30 instructions per closure call, the cost of a counted
callee measured above. That takes closure_fn from +40% to about +11-13%; the two in-function
analogues measure +11.1% and +12.9%. Top-level closure gains little until Change B lands.

**RC-off impact.** None. All in `rc_elide_borrows`, which does not run with RC off.

## 3. Change B: top-level variables as `main`'s locals

**What.** A top-level variable of the entry module whose name appears in no function, lambda,
method or class body, and is never boxed, exported or imported, is bound to an entry-block alloca
of `main` instead of an LLVM global. It is then an ordinary local: R5 borrowed reads, `mem2reg`,
tag split, and no `__mdh_shared_*`. The test is a pass over the AST before codegen.
It over-approximates: any occurrence of the name inside any body keeps the global, whatever
shadowing is in force.

**Invariant.** Only `main`'s own statements can name the variable. Compile time (the AST pass).
Under that invariant the variable is a local in every sense codegen uses.

**Threads and R3.** A thread runs a function, and a function cannot name the variable, so no
other thread can reach the slot. R3's lock exists for slots that two threads can name, which
this slot is not. Values in it may still be shared through containers, exactly as for a
function's locals, and R3 does not cover containers in either case. This part holds with
threads too, so Change B does not need the never-threaded gate. Its borrow elisions still do.

**Ownership table and A1.** No interaction.

**How a mistake shows.** A function that reads a variable made local would fail to compile
(unknown name) or read a stale global. Wrong output or a compile error, caught by goldens; many
already read top-level variables from functions. New golden tests:
- a function reading and assigning a top-level variable;
- a lambda capturing one;
- a thread function reading one;
- a method reading one;
- a top-level variable used only at the top level, across `hae_a_bash` / `gin_it_gangs_wrang`.

Mutant: treat every top-level variable as local. These tests must fail.
Not isolable: the "shadowing ignored" over-approximation, which can only keep more globals.

**Expected saving (estimate).** closure +69% to about +40% (closure_fn, the same program in a
function, measures +40.1%). With Change A, about +11-13%. method +12.5% to about +8.6% (measured
in-function analogue). particle_sim is unchanged: its work is in functions.

**RC-off impact.** Gated on RC, so none: RC-off IR stays identical. Open question Q1: the same
change would also speed up RC-off builds.

## 4. Change C: borrowed local slots (particle_sim)

**What.** A local slot S (unboxed, not a parameter) whose every store is a borrowed read from a
rooted chain becomes a borrowed slot. R4 does the same for parameters: such a slot holds no
reference, so its stores take no retain, and its overwrites, scope exits and epilogue release
nothing. Codegen emits both forms:
- a borrow marker at each store, in place of the retain, as today;
- a new release marker `__mdh_rc_borrow_release` for each release of S's old value or of S
  at an exit.

`rc_elide_borrows` decides per slot. On success it deletes both kinds of marker; on failure
it turns them into `__mdh_retain` and `__mdh_release`, which is exactly R6 code. The decision
is all-or-nothing per slot.

S qualifies when all of these hold:
- (a) Never-threaded program, and S is not boxed.
- (b) The function contains no `setjmp` (try/catch) and no `invoke`/`callbr`. A handler can
  load S on an edge the scan cannot see. This is new: R5's temps die with their statement,
  but a slot is memory.
- (c) Each stored value is a rooted read: a load of variable slot R (R is not S), then index
  or field reads, with every phi edge borrowed or `Skip`. A fresh edge, such as `char_at`'s
  string, disqualifies the slot; Change D removes that edge.
- (d) On every path from each store of S to each use of a value loaded from S (and anything
  derived from it), before the next store of S, there is none of the following:
  - a store into R, or a `Drops` call passed R's address;
  - a release that is not of a value traced to F's own holders (I-own, as in A);
  - a `Drops` runtime call other than releases;
  - a `RunsCode` call, unless it is a direct call of F with `!drops_heap && !writes_globals`.

  Releases of F's own temps and slots are allowed: the chain starts at a variable slot
  (rooted chain).
- (e) R5's escape rules for every value loaded from S. A store into an owned holder or a
  `gie` takes its own reference, so it is not an escape.

**Kind-aware releases, and why they are not the main rule here.** The DEC note asks for
releases of leaf kinds (string, bytes), which can only free that object, to be allowed in
regions. That rule is sound, but it does not unblock `pj`. The region contains the slot
stores of `dx`, `dy`, `d2`, `d`, `force`, `ax` and `ay`. Each releases a value loaded from
the slot, whose kind is unknown before the optimiser runs, which is when the scan runs. The
rooted-chain rule in (d) covers those releases by ownership instead of kind. Kind-aware
releases still have two uses, both optional (section 6):
- unrooted records (holder `None`);
- a cheaper release sequence where a value's tag set is known.

**Invariants and enforcement.**
- Rooted chain: compile time (the stored value's def chain is checked in IR).
- Region (d): compile time.
- I-own: by construction, tested by NOFREE and REPORT.
- (b) and (a): compile time.

**Threads and R3.** Gated off with threads. R3 is not involved, since locals are not
shared slots.

**Ownership table and A1.**
- (d) treats `m`/`s` rows as destructive, as `rc_call_effect` already does (`__mdh_list_push`
  is the only exception), and `b` rows as harmless.
- A1's invariant is what makes a `b`/`m`/`s` call on R's container leave R's container alive.
- The new row guard from A applies here too.

**How a mistake shows.** A use after free of the element `pj` held: a NOFREE abort at the line
that reads `pj`, or wrong numbers without NOFREE. A missed release marker leaks (REPORT live >
0); a double release aborts under NOFREE. New tests, each with exact output, REPORT and NOFREE:
1. `ken p = xs[i]`, then `xs[i] = 0` (element overwrite), then `p[0]`.
2. The same with `heave(xs)` or a pop.
3. The same through a call to a function that mutates `xs`.
4. The same through a closure called in between.
5. `ken p = xs[i]`, then `xs = []` (a store into R), then `p[0]`.
6. `ken p = make()[0]` (a temp-rooted chain), then `p[0]` after the statement.
7. A borrowed `p` read in a `gin_it_gangs_wrang` handler after the try body mutated `xs`.
8. A loop where `p` is reassigned every iteration and returned by `gie p` (escape and exit).

Mutants, each to be seen failing:
- Drop the R-store rule: test 5.
- Drop the destructive-call rule: tests 1-2.
- Drop the summary check: tests 3-4.
- Allow temp roots: test 6.
- Drop (b): test 7.
- Delete release markers on failure instead of converting them: a REPORT leak in one of the
  failing-condition tests.

Not isolable: the "R is not S" clause, since `p = p[0]` already fails (c) because S itself is
stored in the region.

**Expected saving (estimate).** particle_sim: about 74M of its 228M RC instructions (the slot,
measured by removal). That takes it from +15.4% to about +10%. Most of the rest goes with
Change D.

**RC-off impact.** None.

## 5. Change D: element reads without a fresh string edge

**What.** Indexing a string gives a one-character string, fresh from `__mdh_char_at`. That
fresh edge is why every index read of a value of unknown kind parks an owned part and releases
it at the statement's end. Add `__mdh_char_at_interned`, used only when RC is on. It returns an
immortal string from a table indexed by code point, built lazily:
- one entry per distinct code point;
- each entry 16+5 bytes, never freed;
- a table of 0x110000 pointers, allocated in 64K-entry pages on first use.

Its row is `("__mdh_char_at_interned", "bb", Ret::Static)`, so `rc_roots` classes the result
`Skip`. The owned part is then nil on every edge and the temp, its park and its release
disappear at compile time. It also gives Change C's slots an edge set that is all borrowed
or `Skip`.

**Invariant.** The result is immortal (`OBJ_FLAG_IMMORTAL` header): retain and release leave it
alone. The in-place string append reallocates only a buffer the variable itself grew (its
capacity shadow is 0 for any other string, so the first append copies), as it already does
for immortal string literals. Enforced at run time by the immortal header and tested:
- a golden that appends to a character it took from a string (`ken c = s[0]; c = c + "x"`),
  then reads `s[0]` again;
- REPORT unchanged.

**Threads and R3.** Table pages are published with a CAS, and entries are immortal, so readers
need no lock. The first spawn does not need to drain anything.

**Ownership table and A1.** One new row. `Static` means "no reference to take": A1 holds
trivially.

**How a mistake shows.**
- A mutable shared character (wrong output: the append test).
- An over-release of an immortal entry: a no-op; the test is that REPORT is unchanged.
- A leak report from the table: the table is excluded from REPORT as static data.

Mutant: create entries without the immortal flag. The append test fails, or NOFREE aborts on
the second use.

**Expected saving (estimate).** Up to about 154M in particle_sim (the measured read cost),
taking it to about +1-5%. Similar gains in any program indexing values of unknown kind:
expr_eval, dict and list may move by a point or two. Phase 3 first confirms the attribution:
if the hot loop's remaining RC instructions are not the owned-part release, stop and re-plan
before writing runtime code.

**RC-off impact.** None: RC-off codegen keeps calling `__mdh_char_at`, and the new function
is only declared when RC is on.

## 6. Anything else over 15%

Nothing else. After A to D the estimate is every benchmark at about +13% or below. What
remains is structural and not in this round:
- **Unknown-kind values.** Tag tests on stores of values whose kind is unknown: a closure's
  result `x + n` may be a string. That is the residual about 11-13% in the closure analogues.
  Removing it needs type inference over locals and returns.
- **Kind-aware releases (optional, phase 5).** For unrooted records, and to narrow a release
  of a value with a known tag set (for example `{nil, string}`) to `tag == 4` plus a leaf
  release entry. Estimated gain under one point per benchmark. Do it only if a benchmark
  sits just above 15% after phase 4.

## 8. Risks, and what would make me stop

- **Summaries too coarse.** If closure creation and list building make most functions
  `drops_heap` (for example, initialising stores into fresh objects are classed as heap
  stores), A saves less. The release-based rule should avoid that, because initialising
  stores release nothing. Stop and report if closure_fn stays above 20% after phase 1.
- **Hidden edges.** A borrowed slot read on a path the CFG does not show. `setjmp` is the one
  known case (C(b)). Any other (signals, `exit` handlers running user code) would make C
  unsound; stop if one turns up.
- **Threaded programs pay full cost.** With RC as the default, a program that spawns keeps R4
  retains everywhere. That is correct but slower, and no benchmark measures it. Arthur should
  know this before the flip (Q3).
- **Row accuracy.** A and C trust the ownership table. A mislabelled row is a silent
  use-after-free. The guard test catches name-shaped mistakes only.
- **Change B scope.** Imported modules, the REPL and `trace` must keep globals. Stop if any
  tool reads top-level variables by name at run time.
- Stop at any NOFREE abort or REPORT increase that is not understood. Stop at any design fork:
  object header, runtime ABI beyond the one new function, or thread model.
