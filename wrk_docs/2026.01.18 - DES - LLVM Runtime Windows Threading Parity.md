# Design: LLVM Runtime Windows Threading Parity

**Date:** 2026-01-18
**Status:** Reviewed
**Estimated Effort:** 2-3 hours

---

## Problem Statement

The LLVM runtime (`runtime/mdh_runtime.c`) has full threading support on Unix via pthread, but Windows has only stub functions that throw runtime errors. The platform abstraction layer (`runtime/platform/platform_win32.c`) already provides full Windows threading primitives, but they are not being used.

### Current State

**Unix (lines 3189-3686):** Full implementation using pthread
- `MdhThread` wraps `pthread_t`
- `MdhMutex` wraps `pthread_mutex_t`
- `MdhCondvar` wraps `pthread_cond_t`
- `MdhAtomic` wraps `pthread_mutex_t` + `int64_t`
- `MdhChan` (channels) using pthread primitives

**Windows (lines 3687-3736):** Stubs that throw errors
```c
MdhValue __mdh_thread_spawn(...) {
    __mdh_hurl(__mdh_make_string("Threading isnae available on Windows yet"));
}
```

---

## Proposed Solution

Refactor the threading code to use the platform abstraction layer instead of direct pthread calls. This will:
1. Enable Windows threading using the existing platform layer
2. Maintain identical behavior across platforms
3. Simplify the codebase (remove duplicate implementations)

### Approach

**Option A: Unified Implementation** (Selected)
Replace the `#ifndef _WIN32` / `#else` blocks with a single implementation that uses `mdh_thread_*`, `mdh_mutex_*`, `mdh_cond_*` functions from the platform layer.

## Detailed Design

### 1. Data Structure Changes

**Current (Unix):**
```c
typedef struct {
    pthread_t thread;
    MdhValue func;
    MdhValue args;
    MdhValue result;
    int done;
    int detached;
} MdhThread;
```

**Proposed (Platform-agnostic):**
```c
typedef struct {
    mdh_thread_t *thread;      // Platform thread handle (NULL after join/detach)
    MdhValue func;
    MdhValue args;
    MdhValue result;
    int done;
    int detached;
} MdhThread;

typedef struct {
    mdh_mutex_t *mutex;        // Platform mutex
} MdhMutex;

typedef struct {
    mdh_cond_t *cond;          // Platform condition variable
} MdhCondvar;

typedef struct {
    mdh_mutex_t *lock;         // Platform mutex for atomicity
    int64_t value;
} MdhAtomic;

typedef struct {
    mdh_mutex_t *lock;         // Platform mutex
    mdh_cond_t *not_empty;     // Platform condvar
    mdh_cond_t *not_full;      // Platform condvar
    MdhValue *buf;
    int64_t cap;
    int64_t count;
    int64_t head;
    int64_t tail;
    int closed;
    int unbounded;
} MdhChan;
```

**Note:** Removed the extra `mdh_mutex_t *lock` from MdhThread - not needed since `pthread_join()` blocks until thread completion guarantees `result` is set.

### 3. Critical Implementation Details

#### 3.1 Thread Join/Detach Handle Semantics

**Issue:** Platform layer's `mdh_thread_join()` and `mdh_thread_detach()` both free the `mdh_thread_t` handle.

**Solution:** After calling these functions, set `t->thread = NULL`. Check for NULL in subsequent operations.

```c
MdhValue __mdh_thread_join(MdhValue thread) {
    MdhThread *t = __mdh_thread_ptr(thread);
    if (!t) return __mdh_make_nil();

    // Already joined - return cached result
    if (t->thread == NULL) {
        return t->result;
    }

    mdh_thread_join(t->thread, NULL);
    t->thread = NULL;  // Handle freed by mdh_thread_join
    return t->result;
}

MdhValue __mdh_thread_detach(MdhValue thread) {
    MdhThread *t = __mdh_thread_ptr(thread);
    if (!t || t->thread == NULL) return __mdh_make_nil();

    mdh_thread_detach(t->thread);
    t->thread = NULL;  // Handle freed by mdh_thread_detach
    t->detached = 1;
    return __mdh_make_nil();
}
```

#### 3.2 Memory Management

- **Runtime wrappers** (`MdhThread`, `MdhMutex`, etc.): Continue using `GC_malloc()` - these are language-level objects
- **Platform handles** (`mdh_thread_t*`, `mdh_mutex_t*`): Allocated by platform layer with `malloc()` - must be explicitly freed

**Cleanup Strategy:**
- `mdh_thread_join()` frees thread handle - no separate cleanup needed
- `mdh_thread_detach()` frees thread handle - no separate cleanup needed
- `mdh_mutex_destroy()` frees mutex handle - call when mutex no longer needed
- `mdh_cond_destroy()` frees condvar handle - call when condvar no longer needed

**Note:** If a wrapper is garbage-collected without explicit cleanup, the platform handle leaks. This is acceptable for short-lived programs; for long-running programs, users should explicitly destroy mutexes/condvars.

#### 3.3 Timeout Return Values

Platform layer returns `ETIMEDOUT` (110) on timeout. The runtime function should convert this:

```c
MdhValue __mdh_condvar_timed_wait(MdhValue c, MdhValue m, MdhValue timeout_ms) {
    MdhCondvar *cv = __mdh_condvar_ptr(c);
    MdhMutex *mx = __mdh_mutex_ptr(m);
    int64_t ms = __mdh_as_int(timeout_ms);

    uint64_t timeout_ns = (uint64_t)ms * 1000000ULL;
    int rc = mdh_cond_timedwait(cv->cond, mx->mutex, timeout_ns);

    // Return true if signaled (not timed out), false if timed out
    return __mdh_make_bool(rc == 0);
}
```

#### 3.4 Mutex Non-Recursiveness

Both Unix pthread mutexes (default) and Windows SRWLOCK are **non-recursive**. Attempting to lock twice from the same thread will deadlock. This is consistent behavior.

#### 3.5 Thread Wrapper Function

The thread entry wrapper remains platform-agnostic:

```c
static void *__mdh_thread_entry(void *arg) {
    MdhThread *t = (MdhThread *)arg;

    // Register thread with Boehm GC
    GC_stack_base sb;
    GC_get_stack_base(&sb);
    GC_register_my_thread(&sb);

    // Call the user's function
    t->result = __mdh_call_value(t->func, t->args);
    t->done = 1;

    GC_unregister_my_thread();
    return NULL;
}
```

### 4. Timeout Handling

**Current:** `pthread_cond_timedwait()` takes an absolute `struct timespec`

**Platform layer:** `mdh_cond_timedwait()` takes a relative timeout in nanoseconds

This simplifies the code:
```c
// Before (Unix):
struct timespec ts;
clock_gettime(CLOCK_REALTIME, &ts);
ts.tv_sec += ms / 1000;
ts.tv_nsec += (ms % 1000) * 1000000;
pthread_cond_timedwait(&c->cond, &m->mutex, &ts);

// After (Platform layer):
uint64_t timeout_ns = ms * 1000000ULL;
mdh_cond_timedwait(c->cond, m->mutex, timeout_ns);
```

## Implementation Plan

### Phase 1: Fix ETIMEDOUT Definition
1. Move `#ifndef ETIMEDOUT` to top of `platform_win32.c`
2. Verify ETIMEDOUT is defined before use

### Phase 2: Update Data Structures
1. Move type definitions outside `#ifndef _WIN32`
2. Change pthread types to platform layer pointer types
3. Verify compilation on both platforms

### Phase 3: Update Thread Functions
1. `__mdh_thread_spawn()` - use `mdh_thread_create()`
2. `__mdh_thread_join()` - use `mdh_thread_join()`, set handle to NULL after
3. `__mdh_thread_detach()` - use `mdh_thread_detach()`, set handle to NULL after
4. Handle already-joined/detached threads gracefully

### Phase 4: Update Mutex Functions
1. `__mdh_mutex_new()` - use `mdh_mutex_create()`
2. `__mdh_mutex_lock()` - use `mdh_mutex_lock()`
3. `__mdh_mutex_unlock()` - use `mdh_mutex_unlock()`
4. `__mdh_mutex_try_lock()` - use `mdh_mutex_trylock()`

### Phase 5: Update Condvar Functions
1. `__mdh_condvar_new()` - use `mdh_cond_create()`
2. `__mdh_condvar_wait()` - use `mdh_cond_wait()`
3. `__mdh_condvar_timed_wait()` - use `mdh_cond_timedwait()`, handle ETIMEDOUT
4. `__mdh_condvar_signal()` - use `mdh_cond_signal()`
5. `__mdh_condvar_broadcast()` - use `mdh_cond_broadcast()`

### Phase 6: Update Atomic Functions
1. `__mdh_atomic_new()` - use `mdh_mutex_create()`
2. `__mdh_atomic_load()` - lock, read, unlock
3. `__mdh_atomic_store()` - lock, write, unlock
4. `__mdh_atomic_add()` - lock, add, unlock
5. `__mdh_atomic_cas()` - lock, compare-exchange, unlock

### Phase 7: Update Channel Functions
1. `__mdh_chan_new()` - use platform mutex/condvar
2. `__mdh_chan_send()` - use platform primitives
3. `__mdh_chan_recv()` - use platform primitives
4. `__mdh_chan_try_recv()` - use platform primitives
5. `__mdh_chan_close()` - use platform primitives
6. `__mdh_chan_is_closed()` - simple read

### Phase 8: Cleanup
1. Delete the `#else /* _WIN32 */` stub block
2. Remove `#ifndef _WIN32` / `#endif` guards around threading code
3. Verify single unified implementation

## Testing Strategy

### Unit Tests (Interpreter)
The interpreter has threading tests that exercise the same builtins. Search for `test_threading` in the test files.

### Edge Case Tests
1. Join an already-joined thread - should return cached result
2. Detach an already-detached thread - should be no-op
3. Operations on NULL handles - should return error gracefully
4. Timeout accuracy - timed wait should return false on timeout

### Integration Tests
1. Thread spawn and join
2. Mutex lock/unlock
3. Condvar wait/signal
4. Channel send/recv
5. Atomic operations

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| GC thread registration issues | Low | High | Boehm GC supports Windows threads |
| Timeout precision differences | Low | Low | Platform layer handles conversion |
| Memory leaks on thread exit | Medium | Medium | Set handle to NULL after join/detach |
| Deadlock differences | Low | High | Same logic, same behavior expected |
| Double-free on detached threads | Medium | High | Set handle to NULL immediately after detach |

## Success Criteria

1. All threading builtins work on Windows
2. Interpreter threading tests pass on Windows
3. LLVM-compiled threading programs work on Windows
4. No regressions on Unix/Linux
5. No memory leaks or double-frees detected
