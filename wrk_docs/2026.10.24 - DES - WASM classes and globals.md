# WASM backend: top-level variables in daes, and classes (`kin`)

**Date:** 2026-10-24
**Scope:** `src/wasm_compiler.rs`, `src/wasm_runner.rs` only. No interpreter or other backend change.
**Spec:** the interpreter (reference semantics). Builds on
`2026.10.24 - DES - WASM function values and closures.md` (cells, `__mdh_fns`, `__mdh_callN`).

## 1. Goal

- A top-level variable read or assigned inside a top-level `dae` or a class method
  (today: "Top-level variable _ cannae be used inside dae _ in WASM yet").
- Classes: `kin Name { dae init(..) .. dae m(..) .. }`, `kin Sub fae Base`, instances,
  fields, methods, `masel`, constructors and `init`, bound methods (`ken f = obj.m`),
  method defaults, operator overloading (`__pit_thegither__` ...), display and equality.

Out of scope: a `kin` that is not a top-level statement (stays a compile error), a nested
`dae` with defaults, non-constant defaults on top-level daes (both existing restrictions).

## 2. Globals

**Which names.** A *global* is a top-level declared name (the existing `top_level_vars`)
that some top-level `dae` or class method reads or assigns without binding it itself
(the free-name scan already used for closures). Every other top-level name stays a plain
`$main` local, so programs that do not need globals compile exactly as before.

**Representation: one host cell per global, its handle in a guest global.**
`(global $g$name (mut i64) (i64.const 0))`. `$main`'s prologue, before any statement
scope opens, sets each to `__mdh_cell_new(nil)` (or to the dae/builtin value when the
name shadows one, as the existing local-shadow rule does).

- read `g` -> `global.get $g$g; __mdh_cell_get`;
- `g = v` and `ken g = v` -> `__mdh_cell_set` (a top-level `ken` rebinds in place, as the
  interpreter's global environment does);
- every binding site (`ken`, `fer`, catch name, `keek` binding, `kin`, import alias) goes
  through the one `emit_bind`, which knows globals.

A local or parameter of the same name in a dae shadows the global, as in the interpreter.
In `$main` a global is never a local; a lambda in `$main` reaches it directly, not as a
captured cell.

**Reclamation roots.** The cells are allocated while no host scope is open, so they are
never young and never swept: they are permanent roots by construction, like the fixed
nil/true/false slots. Their *contents* are kept by the existing write barrier: `cell_set`
uses `get_mut`, so the innermost scope remembers the (old) cell, its value survives that
scope's sweep, and the remembered cell is promoted to each enclosing scope on exit. This is
the same argument the closure design makes for an old cell taking a young value. No new
root kind, no change to `scope_exit`.

**Divergence (accepted).** Calling a dae that reads a global before the global's `ken`
has run yields `naething` in WASM; the interpreter raises "hasnae been defined". A name
declared only inside a top-level block is treated as a global too (the interpreter would
error); both are error-path-only differences. A top-level `fer` (or a block `ken`) that
reuses a global's name writes the global, where the interpreter makes a fresh inner binding;
this is the existing block-shadowing divergence of this backend, now reaching daes too.

## 3. Classes

### 3.1 Host representation

```
HostValue::Class    { name: String, parent: Handle /* nil = none */, methods: Vec<Method> }
HostValue::Instance { class: Handle, fields: Vec<(String, Handle)> }   // insertion order
HostValue::Bound    { recv: Handle, method: Method }                   // obj.m as a value
struct Method { name: String, index: u32, params: usize, required: usize }
```

`index` is the method's slot in the `__mdh_fns` table. Lookup walks `parent`
(interpreter `find_method`).

- `push_children`: Class -> parent; Instance -> class and every field value;
  Bound -> recv. (A method holds no handles.)
- Display: Instance `<Name instance>`, Class `<kin Name>`, Bound `<dae m>`
  (the interpreter's bound method is a `Value::Function`).
- Equality and dict/creel keys: identity (`Rc::ptr_eq` in the interpreter), via a new
  `ValueKey::Object(handle)` for instances and classes; a Bound is a function value.
- Truthy: always. Type name: `instance`, `class`, `function`.
- Builtins (`tae_string(obj)`, ...): the value bridge passes an instance as a
  `Value::Instance` of a name-only class, cached per handle so identity holds.

### 3.2 Methods as guest functions

Each method compiles like a closure (a `__mdh_fns` slot, queued in `pending`) with the
uniform table shape and these parameters:

```
(func $__mdh$fnK (param $__mdh$env i64) (param $masel i64) (param $p1 i64) .. (param $pn i64)
                 (param $__mdh$argc i64) (result i64))
```

- `masel` is an ordinary parameter, so `Expr::Masel` is a name read. The free-name scan
  counts `masel` as a name, so a lambda or nested `dae` in a method captures it as a cell
  (golden `method_returns_closure_captures_masel`). `masel` outside a method is a compile
  error.
- **Defaults** are evaluated in the callee, matching the interpreter (`bind_params` runs
  in the method's closure environment, so a default sees globals, `masel` and earlier
  parameters, never the call site). The host pads missing arguments with nil and passes
  the argument count as an int handle; the prologue runs `if argc <= i { p_i = default }`
  for each defaulted parameter, before captured parameters are boxed.
- Method bodies see globals (section 2) and call top-level daes directly.

### 3.3 Definition

A top-level `kin` statement compiles to:

```
parent (name lookup, or nil); name -> __mdh_make_class(name_ptr, name_len, parent, line)
for each method: __mdh_class_method(class, name_ptr, name_len, slot, params, required) -> class
emit_bind(Name)
```

`__mdh_make_class` raises the interpreter's "X isnae a class" TypeError when the parent
is not a class. The class name is a declared top-level name (a global if a dae or method
uses it, e.g. a method that builds another instance).

### 3.4 Dispatch: all through the existing host call paths

| Guest construct | Host import | Action on a class value |
|---|---|---|
| `A(args)`, `Klass(args)`, `gaun(xs, A)` | `__mdh_callN` -> `call_value` | Class: allocate Instance, run `init` if found (arity checked), return the instance. Bound: call its method on `recv`. |
| `obj.m(args)` | `__mdh_method_callN` -> `method_call` | Instance: a method (walking parents) wins, then a callable field, else "hasnae been defined". |
| `obj.f` | `__mdh_prop_get` | Instance: a field wins, then a method as a fresh `Bound`, else "hasnae been defined" (now fallible). |
| `obj.f = v` | `__mdh_prop_set` | Instance: field put through `get_mut` (the write barrier). |
| `a + b`, `a == b`, `a < b` ... | `__mdh_add` / `__mdh_eq` ... | left operand an Instance whose class has the overload (`__pit_thegither__`, `__same_as__`, ...): call it with `[b]`, return its result as is. |

A method call is a re-entrant `call_guest(index, nil, [recv, args.., nil pads.., argc])`.
Arity errors use the interpreter's messages (`WrongArity`, or the "expects m tae n
arguments" TypeError when there are defaults).

`__mdh_eq`, `__mdh_ne`, `__mdh_prop_get` and `__mdh_method_callN` become fallible calls
in the guest (a pending-error check after them, only in programs with a `hae_a_bash`),
since an overload, a method or a missing field can now raise.

### 3.5 Reclamation

Same argument as the HOF callbacks (closure design 5.1):

- A constructor allocates the instance in the caller's open statement scope, then runs
  `init` with its own scopes on top. The instance is `init`'s `masel` parameter (a root
  in every `init` scope exit). `init`'s field writes go through `get_mut`: the instance
  is older than `init`'s scopes, so it is remembered and the young field values survive.
  After `init` the instance and its fields are young in the caller's statement scope,
  which cannot close while the host still holds the instance; it reaches a local before
  the next statement boundary.
- `push_children` of Instance (fields and class), Bound (recv) and Class (parent) keep
  the graph alive from any root. **Mutation check:** removing the Instance arm makes the
  field-survival test fail.
- Classes are made by a top-level statement and bound to a `$main` local or a global
  cell, so they are rooted for the program's life.

- New `tests/wasm_validity.rs` tests (each seen to fail first): a dae reading and

  `golden_tests`, all with `--features wasm_runner`.

## 4b. Follow-up: residual divergences (lane W7, MDH-BUG-FLU-00125 / 00123)

The divergences accepted in sections 1 and 2 are now closed:

- **Block scoping** (`resolve_scopes`, a pass before each function is compiled). Only a
  block (and a `fer`'s per-iteration scope, which its body block shares) opens a scope,
  as in the interpreter. A binding in a nested scope of a name visible ootside it (an
  enclosing binding, a global, a dae or a builtin) gets its own local `name$sN`, so a
  block `ken` or a top-level `fer` never writes the outer variable or the global. A
  second `ken` in the same scope rebinds: on a cell it is a `cell_set`, so closures made
  in between see the new value (MDH-BUG-FLU-00123). A catch name or keek binding counts
  as only maybe bound, so a later `ken` there still makes a fresh cell. Results are keyed
  by node address (`binds`, `uses`, `captures`); a node the pass did not see falls back to
  the old function-wide name, so nothing synthesised can miscompile silently.
- **Forward globals.** A global's cell starts as `UNSET_GLOBAL` (a handle that is never a
  value). Reads and assignments go through `__mdh_global_get`/`__mdh_global_set`, which
  raise the interpreter's "hasnae been defined yet" error on it. `ken` still `cell_set`s.
- **Defaults everywhere.** A top-level dae, nested dae or method wi' defaults takes the
  argument count last and evaluates its defaults in the callee (after the env is unpacked,
  before captured parameters are boxed). Direct calls pass nil pads and the count; a
  function value carries `required`, and the host's `call_with_defaults` (shared with
  methods) checks the arity and pads.
- **A `kin` inside a function.** Each method gets an env list of the cells it captures,
  stored in the class (`Method.env`); `push_children` traces it from the class and from a
  bound method (mutation-checked: dropping it fails `a_kin_inside_a_dae_captures_its_variables`).
- **Block expressions and destructuring** are compiled (`compile_stmts` inside an
  expression is sound: anything on the operand stack is older than the inner scopes).
- Operator overloads already restore the line through `call_guest`; a test now pins it.

Golden parity allowlist 11 -> 1. The one left, `showcase_bothy_adventure`, passes a dict
of lambdas to the builtin `contains`: the builtin bridge cannot carry a function value.
