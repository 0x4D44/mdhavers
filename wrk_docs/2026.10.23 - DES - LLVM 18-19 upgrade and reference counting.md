## 0. Summary of the recommendation

Two independent programmes. Each stage leaves trunk green and can be approved or rejected alone.

| Stage | What | Needs | Size | Risk |
|---|---|---|---|---|
| U1 | New pass manager on LLVM 15, inkwell 0.4 | nothing | 1 file, ~60 lines | medium: inlining may expose codegen UB |
| U2 | Bump inkwell 0.4 to 0.11 (or the newest >= 0.7), still `llvm15-0` | U1 optional | 2-3 files, ~500-800 mechanical edits | low-medium |
| U3 | Opaque-pointer cleanup (`context.ptr_type`, drop no-op casts) | U2 | 1-2 files, ~300 edits | low |

| R1 | Counts maintained, frees disabled, "would-free" checker | R0 | runtime + codegen | medium |
| R2 | Frees enabled (leaves first, then containers) | R1 green | runtime | high |
| R3 | Thread-safe counts | R2 | runtime | medium |
| R4 | Optional: exception cleanup stack; optional: cycle collector | R2 | runtime + codegen | medium-high |

U-stages and R-stages do not depend on each other. I recommend U1-U4 first: they are smaller, and
R-stage validation (ASan through the new PM) is easier after U1.

### 1.4 Runtime value representation

- `MdhValue = { uint8_t tag; int64_t data; }`, 16 bytes, passed by value
  (`runtime/mdh_runtime.h:39-43`; LLVM side `src/llvm/types.rs:61-62`). Tags 0-14
  (`mdh_runtime.h:15-31`, mirrored in `types.rs:11-26`).
- Immediate in `data`: Nil, Bool, Int, Float. Pointer in `data`: everything else.
- String: a bare NUL-terminated `char*` with no header (`__mdh_make_string`,
  `mdh_runtime.c:254-262`, via `GC_strdup`). `struct MdhString` (`mdh_runtime.h:59-62`) exists but
  is not the value payload **(inferred from `__mdh_make_string`)**. Literals are LLVM globals
  (71 `build_global_string_ptr`/`const_string` sites in `codegen.rs`, not all value literals).
- List: `MdhList {items, length, capacity}` (`mdh_runtime.h:52-56`), two allocations
  (`__mdh_make_list`, `mdh_runtime.c:264-275`). Ranges are materialised as lists
  (`__mdh_range`, `mdh_runtime.c:6885`, allocates an `MdhList`).
- Dict/Set: a stable handle `intptr_t[3]` (`__mdh_kv_new_handle`, `mdh_runtime.c:4012`) pointing
  at a payload `[count][marker][k,v,...]` (`__mdh_empty_dict`, :4020-4031). `__mdh_dict_set`
  updates in place or appends (:4276-4291). (The HLD's "every insert copies the dict" looks
  out of date for set; not re-checked for other paths.)
- Closure: one block `[cap][len][fn, captures...]`, 16-byte header plus 16 bytes per slot
  (`codegen.rs:13441-13451`). Captures are **cells**: a captured variable's storage holds a
  1-element list, and reads/writes go through element 0 (`codegen.rs:573-576`,
  `ensure_boxed_variable` :8927).
- Instance: `[class_name_ptr][field_count][fields...]`, `malloc`ed in codegen (`codegen.rs:38440-38444`)
  and grown with `realloc` when fields are added (`codegen.rs:38027-38035`). A realloc can move
  the object, so any other alias holds a stale pointer **(inferred hazard, exists today)**.
- Bytes: `MdhBytes {data, length, capacity}` (`mdh_runtime.h:65-69`).
- Native: thread/mutex/condvar/atomic/channel are 1-based indices into a global handle table
  that is never shrunk (`mdh_runtime.c:3452-3495`). Tri objects are `MdhNativeObject`.
- Function and Class tags point at code or LLVM globals, not heap.
- Exceptions: per-thread, growable `jmp_buf*` stack (`mdh_runtime.c:10140-10170`, `__thread`),
  `jmp_buf` storage is a 512-byte entry-block alloca (`codegen.rs:49`, :36056-36069), `setjmp` is
  declared `returns_twice` (`codegen.rs:3348-3378`), and `gie`/`brak`/`haud` pop handlers
  (`emit_try_pops`, `codegen.rs:13049-13068`). The HLD 7.2/7.4 notes on a fixed global 64-entry
  stack and dangling handlers are out of date. The thrown value sits in
  `static __thread MdhValue __mdh_last_error` (`mdh_runtime.c:10143`).
- Threads are real OS threads in native code: `mdh_thread_create` (`mdh_runtime.c:3679`),
  each worker wraps its body in its own try (:3643-3664) and `thread_join` re-raises (:3687-3707).

## 3. Reference counting design

### 3.1 What is counted

| Counted (heap objects) | Not counted |
|---|---|
| String (`char*` payload) | Nil, Bool, Int, Float (immediates) |
| List (the `MdhList` struct; `items` is a buffer it owns) | Function (code pointer) |
| Dict and Set (the handle; payload is a buffer it owns) | Class (LLVM global) |
| Closure block | Native handles (table index; table stays immortal, as today) |
| Capture cell (today a 1-element list, so it is a List) | String literals and other static data: **immortal** |
| Instance | |
| Bytes | |
| Bound method | |
| Tri `MdhNativeObject` (kind-specific destructor) | |

Internal buffers (`MdhList.items`, dict payload, string-builder buffers, the try stack) are not
counted: they are owned by exactly one object and freed by its destructor.

### 3.2 Where the count lives

A 16-byte header **immediately before** the payload pointer that `MdhValue.data` already holds:

```
[ int64 refcount | uint32 kind | uint32 flags ] [ payload: char data / MdhList / handle / ... ]
                                                ^ MdhValue.data points here (unchanged)
```

- `data` keeps pointing at the payload, so the ~1,000 existing GEPs and every C function that reads
  `(char*)v.data` or `(MdhList*)v.data` stay as they are. This is the main reason to prefer a
  prefix header over a payload-embedded count.
- 16 bytes keeps payload alignment at 16.
- `flags` bit IMMORTAL: retain/release are no-ops. Used for literals, class-name strings and anything
  static. Literals become constant globals `{i64 IMMORTAL, i32 kind, i32 flags, [n x i8]}` and the
  value points at the chars. Retain/release test the flag before writing, so read-only literals
  are never written.
- `__mdh_obj_alloc(kind, size)` returns payload pointer; `__mdh_buf_alloc/realloc/free` for
  uncounted buffers. `__mdh_retain(MdhValue)` / `__mdh_release(MdhValue)` switch on tag (immediate
  tags return at once). Codegen may inline the tag test and call out only for heap tags.
- Release at zero runs a per-kind destructor that releases children. Destruction is **iterative**
  (an explicit work list), never recursive, so a long list of lists cannot overflow the C stack
  (same lesson as `src/value.rs:Drop`, see `lessons_learnt.md`).
- **Release never runs user code and never hurls.** There are no finalizers. This invariant is
  what makes the exception rules in 3.4 safe.

### 3.3 Ownership convention

The Python C-API convention, chosen because it matches how the runtime is already written:
- **Arguments are borrowed.** A callee never releases an argument. A callee that stores an argument
  (`__mdh_list_push`, `__mdh_dict_set`, closure creation, `thread_spawn`, `chan_send`) retains it.
- **Results are owned (+1).** Every runtime function and every compiled function returns a new
  reference. That includes getters (`xs[i]`, `dict_get`), because a borrowed getter result dies if
  the container is mutated while the value is in use (`f(xs[0])` where `f` clears `xs`).
- Known places that today return a stored or argument value, which must add a retain:
  `__mdh_get_last_error` (`mdh_runtime.c:10172`), `__mdh_thread_join` returning cached
  `t->result` (:3687-3707), `__mdh_dict_set` returning `dict` (:4276-4291). A full audit of the 348
  declared runtime symbols (HLD 7.3) is part of R0; I recommend recording owned/borrowed in one
  table that both `mdh_runtime.h` (as `MDH_OWNED`/`MDH_BORROWED` macros) and codegen declarations
  are checked against.
- Raw interior pointers (`__mdh_get_string` returning `const char*`) stay borrowed and must not
  outlive the `MdhValue` they came from in the same statement.

### 3.4 Retain/release insertion rules in codegen

| Construct | Rule |
|---|---|
| **Local slot** (entry-block alloca, `create_entry_block_alloca` `codegen.rs:27728`) | Initialised to nil in the entry block, so releasing it on any path is safe. A slot owns one reference. |
| **Assignment** `x = e` | Evaluate `e` to an owned value (retain if it was a borrowed load). Then `old = load x; store new; release old`. Store before release, so a slot never holds a freed pointer and self-assignment is safe. |
| **Temporaries** | Each owned intermediate result is pushed on a per-statement temp list; after the consuming call, release it. A result that is moved into a slot or returned is removed from the list (a move, no retain/release pair). |
| **Arguments** | Passed borrowed. A parameter's slot retains on entry and releases at exit (simple, uniform; an optimisation can skip it for parameters never assigned). |
| **Returns** `gie e` | The value is owned. All paths branch to one epilogue that releases every local slot, then returns. Returning a local: retain (or move) before the epilogue. Existing `emit_try_pops` stays in front of the branch. |
| **Captured cells** | The cell (a List) holds +1 on its value. The closure block holds +1 on each cell; the variable's slot holds +1 on the cell. Closure destructor releases cells. |
| **Globals** | A global slot owns one reference; assignment uses the same load/store/release order. Globals are released by `__mdh_shutdown` at normal exit only (for leak-test cleanliness), not on `exit()` from an uncaught hurl. |
| **Containers** | Store retains the value (and key); overwrite releases the old element after storing; remove/pop transfers the container's reference to the caller (no extra retain). Destructor releases all elements. |
| **Shadow caches** | Shadows (`int_shadows`, `string_len_shadows`, `string_cap_shadows`, `list_ptr_shadows`, `codegen.rs:559-571`) are borrowed views of a slot, valid only while the slot is unchanged. See 3.7. |

**Exceptions (`hurl` / `hae_a_bash`, `setjmp`/`longjmp`).** `longjmp` skips every release that would
have run between the `hurl` and the handler: temporaries in flight, locals of the frames it unwinds,
and C runtime temporaries (e.g. `__mdh_hurl_at` building its message, `mdh_runtime.c:10190-10205`).
The design guarantees **leaks, never double frees**, on that path:
1. A release happens only on normal control flow, after the store that made it safe. A `longjmp`
   can only skip a release, never repeat one.
2. A slot always holds a live owned reference or nil (store-then-release; release cannot hurl).
   So after `longjmp` the handler frame's slots are consistent, and its normal epilogue releases
   them exactly once. Slots are memory (allocas), not registers, and `setjmp` is `returns_twice`
   (`codegen.rs:3363-3378`), so their values are defined after `longjmp` **(inferred: relies on
   the optimizer honouring `returns_twice`; must be tested at -O3)**.
3. Unwound frames' locals and temporaries are leaked. That is bounded per hurl.
4. `__mdh_last_error` (`mdh_runtime.c:10143`) owns the thrown value: `hurl` stores it (releasing
   the previous one), `get_last_error` returns +1. A worker thread's error moves into `t->error`.

To remove the leak (stage R4, optional): a per-thread **cleanup stack**. Each compiled frame that
owns slots registers their addresses on entry and pops on exit; `__mdh_try_push` records the
cleanup depth; on `longjmp` the handler releases every registered slot above that depth before
running the catch body. Cost: a push/pop per call frame. Alternative: replace `longjmp` with
error-flag returns checked after every call (larger codegen change, affects all backends' parity
on error paths). I recommend shipping R2 with documented exception leaks and measuring first.

### 3.5 Threads

Native threads are real (`mdh_runtime.c:3679`). Values cross threads through `thread_spawn`
arguments, `thread_join` results, channels (`MdhChan`, `mdh_runtime.c:3437-3448`), globals and
captured cells. Non-atomic counts would race to double frees.

Proposal (R3): **counts are non-atomic until the first `thread_spawn`, atomic afterwards.**
- A global `__mdh_threads_started` flag, set by `__mdh_thread_spawn` before `mdh_thread_create`.
  Thread creation is a happens-before edge, so every op after it sees the flag.
- Retain/release test the flag (a well-predicted branch) and use `__atomic_fetch_add` relaxed for
  retain and `__atomic_fetch_sub` acq_rel for release once set. Single-threaded programs (most of
  the corpus) pay one branch.
- Slot updates on **shared** storage (globals, captured cells) after threads start must swap
  atomically (`__atomic_exchange`) and then release the old value, or two threads can release the
  same old value. Locals are thread-private and need nothing.
- RC does not fix existing data races on containers (two threads pushing to one list). Today those
  corrupt memory silently; after RC they can also double-free. Document: shared mutable containers
  need a `mutex`. A later option is biased RC (owner thread non-atomic) if profiling shows the
  atomic path matters.

### 3.6 Cycles

Plain RC leaks cycles. Cycles this language can make: a list or dict that contains itself, instances
that point at each other, and **recursive closures**: a nested `dae` that refers to itself goes
through its own capture cell, so cell -> closure -> cell is a cycle at every creation
**(inferred from the boxing scheme, `codegen.rs:573-576`, :13427-13440)**. Top-level functions are
code pointers and do not form cycles.

Proposal: **no cycle collection in R2; cycles leak and are documented.** The R1 counting harness
reports how much the corpus leaks to cycles. If it matters, add a synchronous trial-deletion
collector (Bacon-Rajan: buffer possible roots on decrement-to-nonzero, scan periodically) as R4.
The recursive-closure case can also be special-cased: a closure's self-reference can be held weak
**(design option, not evaluated)**.

### 3.7 Shadow caches and in-place mutation

Today a stale shadow reads stale but still-allocated memory. After R2 it is a **use-after-free**.
So R0 must first make shadows invalidate (or reload) on every reassignment, call that may reassign
via a cell, and catch-path entry (HLD 7.4 lists the hazard; `sync_all_shadows` `codegen.rs:6015` is
the write-back side).

In-place string append (`compile_string_self_append`, `codegen.rs:14771`, realloc at :14927) and
in-place list growth are only legal when the object is uniquely owned: **`refcount == 1` and not
immortal**, else copy first. That turns the HLD 7.4 "writes into read-only literals" and "aliased
in-place append" hazards into correct copy-on-write, which is a benefit of RC.

### 3.8 Prerequisites (stage R0, each independently useful)

1. **One allocator.** Route all 41 codegen `malloc`/`realloc` calls and all 115 `GC_*` sites through
   `__mdh_obj_alloc` / `__mdh_buf_alloc`. This also makes Boehm viable as an alternative.
2. **Stable instance identity.** Instances become a fixed header plus a separately allocated field
   buffer (like `MdhList`), instead of `realloc` of the object (`codegen.rs:38027-38035`).
3. **String literals and class-name strings get immortal headers** (3.2).
4. **Shadow invalidation fixed** (3.7).
5. **Owned/borrowed table** for the runtime ABI (3.3).
6. **Audit that no `MdhValue` points into the interior of another object** (e.g. substring or
   slice helpers returning `base + offset`) **(not audited)**. A header lookup on such a pointer
   would read garbage.

### 3.9 Validation

- **R1 "count but never free" mode.** Counts are maintained, but reaching zero marks the object
  DEAD (poisons the header) instead of freeing. Any later retain, release or runtime access of a
  DEAD object aborts with the allocation site. This finds every would-be use-after-free without
  any crash risk, before frees are switched on.
- **Leak-count harness.** A debug build of `__mdh_obj_alloc` counts live objects per kind;
  `MDH_RC_REPORT=1` prints them at `__mdh_shutdown`. A test runs every golden natively and asserts
  live == 0 except for an allowlist of known cycle and exception-leak tests.
- **Underflow assert:** release of a count already at 0 aborts (debug builds).
- **ASan + LSan:** build the C runtime with `-fsanitize=address` and add the `asan` pass to the
  new-PM pipeline for the generated object (after U1; pipeline name per LLVM's `PassRegistry`
  **(unverified)**), link with `-fsanitize=address`. Run the golden corpus. LSan replaces the
  harness for leak detail.
- **TSan** for the thread tests once R3 lands.
- **Differential check:** every golden's native output must equal the interpreter's (the existing
  `tests/backend_parity.rs` and golden runner), at -O0 and -O3, in normal and R1 modes.
- **Iterative teardown test:** a 10^6-deep nested list freed without stack overflow.

### 3.10 Staged RC plan

- **R0.** Prerequisites 3.8. No behaviour change except fixed hazards. Files: `mdh_runtime.c/.h`,
  `codegen.rs`, `gc_stub.c`, `tri_runtime.rs`. Check: goldens + parity.
- **R1.** Header, retain/release, insertion rules, DEAD-marking instead of free; harness and
  underflow assert. Check: goldens with zero DEAD-access aborts.
- **R2.** Enable frees: strings and bytes first, then lists/dicts/instances/closures. Check: goldens,
  ASan/LSan, harness with allowlist.
- **R3.** Atomic-after-spawn counts and atomic shared-slot swaps. Check: thread tests under TSan.
- **R4 (optional).** Cleanup stack for exceptions; cycle collector. Decide on R2's measurements.

## 4. Risks, effort shape and open questions

### 4.1 Risks

| Risk | Stage | Mitigation |
|---|---|---|
| New PM inlining exposes UB already in generated IR | U1 | goldens at all -O levels; fix shadows (R0.4) early if it bites |
| inkwell API churn larger than listed | U2 | the first `cargo check` gives the real list; helper fns absorb repeated patterns |
| Windows has no easy llvm-sys-ready LLVM 19 | U4 | decide whether Windows native stays supported; document a prebuilt source |
| Owned/borrowed audit misses a runtime function | R1-R2 | R1 DEAD-marking catches it before frees exist |
| `longjmp` with optimised slots | R1-R2 | slots are allocas, `returns_twice` set; test try/catch goldens at -O3 |
| Cross-thread double free | R3 | atomic counts and slot swaps; TSan |
| Performance regression from retain/release on every load | R1 | measure with `benchmarks/`; later elide pairs for non-escaping locals |
| `codegen.rs` size (48,651 lines) makes insertion error-prone | R1 | centralise in a few helpers (load-var, store-var, call-runtime) rather than editing 572 builtin arms one by one (HLD 7.3) |

### 4.2 Effort shape (files, steps, risk; no time estimates)

- U1: 1 file, 1 step. Medium risk.
- U2+U3: ~3-5 files; roughly 180 `ptr_type`, 279 `.left()`, 120 cast edits, mostly mechanical
  (a Sonnet worker with a strong check: compile + goldens). Low-medium risk.
- U4: ~7 files, mostly scripts and docs, plus 2 platform build checks. Medium risk (packaging).
- R0: 2 C files, `codegen.rs`, 1 Rust runtime file; ~160 allocation sites, 1 layout change
  (instances), 1 literal-layout change, shadow fix. Medium risk.
- R1: the largest step. Codegen helpers for var load/store, temp tracking per statement, epilogue
  blocks, plus the 348-symbol ownership audit. High effort, medium risk thanks to no-free mode.
- R2: runtime destructors and a switch. High risk, small code.
- R3: runtime only, small. Medium risk.
- R4: each item a separate design note first.
