# DES - R1 refcount insertion plan (native backend)

**Date:** 2026-10-25
**Parent:** `2026.10.23 - DES - LLVM 18-19 upgrade and reference counting.md` (DES F6), sections 3.2-3.4,
3.9 and 3.10 stage R1. DEC round 2: RC only; exception-path and cycle leaks accepted; atomic
counts after the first spawn are R3, not R1.
**Scope:** `runtime/gc_stub.c`, `runtime/mdh_runtime.{c,h}`, `src/llvm/{codegen,types,ownership}.rs`,
native tests. Nothing is freed in R1.

## 1. Header and allocator

- Every object from `__mdh_obj_alloc(kind, size)` is `malloc(16 + size)` with the DES 3.2 header in
  front: `{ i64 refcount = 1, u32 kind, u32 flags = MDH_OBJ_MAGIC }`; the payload pointer (what
  `MdhValue.data` holds) is unchanged in meaning. `__mdh_obj_realloc` reallocs header and payload
  together (`NULL` allocates a string object). Buffers (`__mdh_buf_*`) get no header.
- `flags` = magic `0x4D440000` in the high half, bits `IMMORTAL 0x1`, `DEAD 0x2`. The immortal literal
  headers R0.3 emits gain the magic. A heap-tagged value whose header lacks the magic aborts
  ("nae object header"): that catches a static or interior pointer (DES 3.8 item 6, not audited in R0).
- Counted tags: String, List, Dict, Instance, Set, Closure (closures and bound methods), Bytes.
  Not counted: Nil, Bool, Int, Float, Function, Class, Range (no heap payload), Native (tri objects and
  sockets; they keep living as today, DES 3.1 row deferred to R2). Codegen and runtime test
  "heap tag" with one mask `MDH_RC_TAG_MASK`.

## 2. Retain / release / DEAD (runtime)

- `__mdh_retain(MdhValue)`, `__mdh_release(MdhValue)` (C API) and `__mdh_rc_retain_obj(i64 data)`,
  `__mdh_rc_release_obj(i64 data)` (what codegen calls after its inline tag test).
- Retain: no-op for immortal; abort if DEAD; `refcount++`.
- Release: no-op for immortal; abort if DEAD (that is the **underflow assert**: a live object never
  sits at 0 because it is born at 1 and marked DEAD on reaching 0); `--refcount`; at 0 run the
  kind's child releases with an explicit work list (never recursive), then poison: `flags |= DEAD`,
  `refcount` := the mdhavers line that killed it. Memory is kept (R1), so a later touch is detected,
  not a crash.
- Child releases (what R2's destructors will do minus `free`): list items; dict/creel keys and
  values (live slots only); closure/bound-method elements 1..len-1; instance field keys and values;
  string, bytes: none.
- Abort message (stderr, then `abort()`): `mdhavers rc: <op> o a deid <kind> (it dee'd at line M)
  at line N`. The allocation site is not recorded (no room in 16 bytes); the death line plus the
  current line is cheap and pins the bug.
- Runtime access check: the central accessors (`__mdh_get_string`-style helpers, list get/len,
  dict get, `blether`, `to_string`) call `MDH_RC_CHECK(v)`; codegen's inline fast paths are covered
  by the retain every read does (section 3).
- **Off by default (lead decision, after checkpoint 3)**: counts are not atomic and a counting
  bug aborts, so nothing reaches users before R2/R3. `MDH_RC=1` in the compiler's environment
  (or `LLVMCompiler::with_refcounting(true)`) turns codegen insertion on; main then calls
  `__mdh_rc_enable`, which sets the kinds (MDH_RC_KINDS, else the default). Off, the IR is
  byte-identical to trunk, the runtime counts nothing and heap objects get no header.
- Cheap paths: parameters, captures and `masel` stay borrowed until something stores into
  their slot (then the prologue gets a retain); reads of local unboxed variables stay
  borrowed for their statement unless the slot is stored into while it is open (then the
  read is retained and parked); a value whose tag is a constant non-heap tag needs nothing.
- **DEAD mode is always on in R1** (with counting on): with no frees there is nothing else to do at zero, and the cost
  is one flag test in retain/release. R2 turns "poison" into "free" and keeps poison-only behind
  `MDH_RC_NOFREE=1` for debugging.
- **Staging mask:** `__mdh_rc_kinds` (bit per kind) says which kinds are counted; retain/release
  return at once for other kinds, so an uncounted container never runs child releases. Checkpoint 3
  counts strings only; each later checkpoint adds a kind; the final R1 state counts all of them.
- Threads: counts are non-atomic (R3 makes them atomic after the first spawn). Thread goldens are
  run repeatedly to watch for count races.

## 3. Codegen insertion (driven by the ownership table)

The design keeps DES 3.3 (arguments borrowed, results owned) and centralises insertion in a few
helpers instead of editing builtin arms one by one (DES 4.1 last row).

1. **Expression results are owned.** `compile_expr` becomes a wrapper around the existing match
   (`compile_expr_inner`). For every `MdhValue` result it either *takes* an existing +1 or *retains*,
   then parks the value in a **temp slot** of the current temp scope:
   - takes (no retain) when the value is fresh: a direct call whose callee row in
     `RUNTIME_OWNERSHIP` is `Ret::Fresh`; a call to a compiled mdhavers function, lambda, method or
     late dispatcher (they return +1); a value built from an `__mdh_obj_alloc` result (literal
     lists, dicts, closures, instances); a phi whose incomings are all fresh. Recognised by looking
     at the LLVM value, so the ~570 builtin arms need no edit. A value is taken at most once (a
     "taken" set), so an arm that returns a sub-expression's value gets a retain, not a second take.
   - retains everything else (`Ret::Stored`/`Arg` runtime results, variable/field/element loads,
     box reads). Unknown shapes default to retain: a misclassification leaks, it cannot free early.
   - skips values whose tag is a compile-time constant outside the heap mask, and immortal literals.
2. **Temporaries.** A temp slot is an entry-block alloca initialised to nil. Parking does
   `old = load; store v; release old`. A temp scope (each statement; each loop condition and
   per-iteration expression) ends with `load; store nil; release` for its slots. Blocks ended by
   `gie`/`brak`/`haud`/`hurl` skip that; the slot is released by its next parking or by the
   function epilogue, so nothing leaks on those paths.
3. **Variable slots** (locals, params, captures, `masel`, loop vars, catch vars, globals): every
   alloca from `create_entry_block_alloca` is nil-initialised in the entry block and registered as
   an owned slot of its function. Every store goes through `store_slot(ptr, v)`:
   `old = load; retain v; store v; release old` (store before release, DES 3.4). Stores of values
   statically Int (the int-shadow paths) stay plain stores. A move variant (no retain) is used only
   where the value is a fresh +1 the codegen made itself (box cells).
4. **Function epilogue.** After a function body is compiled, a post-pass (like
   `restore_current_line_on_return`) inserts, before every `ret`, a release of every owned slot and
   temp slot of that function. `gie e` retains its value before the branch (the caller gets +1);
   every other `ret` in an owned-return function returns +1 or an immediate. Main releases its
   slots and then every user global before `ret 0`, so the harness sees what really leaked.
5. **Arguments** are borrowed; the callee's param slot retains on entry (rule 3) and releases at the
   epilogue (rule 4).
6. **Containers and objects built inline** (list/dict literals, closure and bound-method blocks,
   instance fields, box cells, inline index/field sets): the store retains the value (and key);
   an overwrite releases the old element after the store.
7. **Runtime side:** args coded `s` in the table retain what they store; overwrites release the old
   value after storing; functions that copy elements into a new container ("shares elements of
   arg 1") retain each copied element; `Ret::Stored`/`Arg` rows stay as they are (codegen retains).
   `hurl` stores the thrown value with a retain; `get_last_error` is `Stored`.
8. **Captured cells:** a cell is a List: it holds +1 on its value (push/box_set retain), the closure
   block holds +1 per cell (rule 6), the variable slot holds +1 on the cell (rule 3).
9. **Exceptions:** `longjmp` skips releases only (leaks, never double releases): slots are
   store-then-release, and the try pinning of R0.4 is extended to temp slots so values are in memory
   after `setjmp` returns twice.
10. **Shadows** (int, list pointer, string len/cap) stay borrowed views of their slot. In-place
    string append keeps its "capacity 0 = not owned" rule; it only reallocs a string no one else has
    read since it was made, which is the refcount == 1 case of DES 3.7.

## 4. Harness (DES 3.9)

- Always-on per-kind counters (relaxed atomics): allocated and died. `MDH_RC_REPORT=1` prints at exit
  (atexit, so `exit` from an uncaught hurl reports too): `mdhavers rc: live <kind>=N ... total=N`.
- `__mdh_rc_live(kind)` exposes the count for tests.
- R1 gate: native goldens with zero DEAD aborts. Live counts are reported, not gated (exception and
  cycle leaks accepted; the allowlist gate is R2).

## 5. Cost

Per counted value: an inline tag test, and a call for heap tags. Temp slots are allocas that mem2reg
promotes outside functions with a try. Expected hot-path effect: integer code (fib) pays tag tests that
mostly fold away on constant tags; string/list/class loops pay a retain/release call pair per value
read. Measured at checkpoints 3 and 4 (fib(32), an allocation loop, a class loop; median of 5 vs trunk);
stop if any regresses more than 25%.

## 6. Checkpoints

1. This plan. 2. Runtime: header, retain/release, DEAD, underflow, mask, harness, C-level tests.
3. Codegen helpers and insertion, strings counted; native goldens with zero aborts; timings.
4. Lists (and cells), dicts/creels, instances, closures/bound methods, bytes: one commit each, each
   with goldens at zero aborts; timings after the last.
