## Goals

1. Maintain **100% instantiation coverage** as a regression guard (floor).
2. Avoid destabilizing runtime behavior while improving other metrics (lines/regions) opportunistically.
3. Prefer:
   - deterministic tests
   - `#![cfg(coverage)]` coverage-only integration sweeps
   - small, semantics-preserving refactors that remove closure-only instantiations

## Stage 2 — LLVM compiler interface (`src/llvm/compiler.rs`) (medium wins)

Current: **11 missed instantiations**.

Likely causes (based on prior patterns in this repo):
- “status” / terminal-color code paths not executing under test harnesses
- generic error adapters not being exercised with particular error types
- duplicated instantiations between unit-test crate and dependency crate

Approach:
1. Generate `--show-instantiations` HTML and list exact missed symbols.
2. Prefer coverage-only tests that:
   - trigger early error branches (no external toolchain dependency)
   - exercise status formatting paths in a controlled way (avoid relying on TTY detection)
3. If TTY-dependent paths are the culprit, consider `cfg(coverage)`-only shims:
   - e.g., call formatting helpers even when output is disabled (no user-visible output), purely for coverage.

Exit criteria:
- Reduce LLVM compiler misses to near-zero while keeping compilation behavior unchanged.

## Stage 3 — Token DFA / Logos state machine (`src/token.rs`) (harder, bounded)

Current: **19 missed instantiations** (these tend to be “goto”/state-machine edges).

Approach:
- Build a small table of token strings that drive the lexer through rare transitions.
- Add a `#![cfg(coverage)]` integration test that feeds the lexer a curated corpus and asserts it terminates + produces tokens.
- If specific DFA edges remain uncovered, add a minimal fuzz-like generator that enumerates short ASCII strings (bounded length) and ensures lexing runs.

Exit criteria:
- Reduce misses materially (even halving these misses is a big overall win).

## Stage 4 — Interpreter (`src/interpreter.rs`) (largest remaining hotspot)

Current: **72 missed instantiations**.

Approach:
1. Use `--show-instantiations` output to categorize misses into themes:
   - error-only branches
   - native/builtin dispatch arms
   - concurrency/networking stubs
   - rarely used Value shapes / NativeObject behavior
2. Add focused, deterministic integration tests (prefer `#![cfg(coverage)]`):
   - avoid real networking where possible (use existing stubs or local-only sockets)
   - avoid timing-dependent concurrency checks (assert invariants, not schedules)
3. Where misses are due to duplicated instantiations across crate instances, ensure both:
   - unit tests (unit-test crate instance)
   - integration tests (dependency crate instance)

Exit criteria:
- Reduce interpreter instantiation misses by 25–40 without increasing flakiness.
