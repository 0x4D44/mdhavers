## 1. Executive Summary

This document presents the design for **Swarm Symphony** - a swarm intelligence simulation that showcases mdhavers' 2D graphics, sample-based audio, and networking capabilities. The app demonstrates emergent behavior through hundreds of AI-controlled agents, with their interactions sonified into a dynamic musical composition and visualized in 2D isometric projection.

**Key Design Decisions (from review feedback):**
- **2D Isometric visualization** (mdhavers has 2D raylib only, no native 3D)
- **Sample/MIDI-based audio** (no synthesizer API available)
- **Single-threaded cooperative design** (no user-defined function threading)
- **500-2000 agent target** (interpreter performance constraints)
- **MVP: Single-node first**, distributed features as stretch goal

## 3. System Overview

### 3.1 Concept Description

**Swarm Symphony** is an emergent system where:

1. **Hundreds of autonomous agents** follow simple behavioral rules (separation, alignment, cohesion)
2. **Agent interactions generate music** - collisions trigger percussion samples, flocking affects harmonic layers, predator-prey dynamics create tension/release
3. **Networked spectators** can connect to watch and listen
4. **AI/human players** can inject agents, modify rules, and influence the simulation via text commands

### 3.2 Key Features

| Feature | Description |
|---------|-------------|
| **Emergent Behavior** | Simple rules create complex, mesmerizing patterns |
| **Sample-Based Music** | Agent activity triggers and modulates pre-rendered sounds |
| **Network Spectating** | Clients can connect to watch simulation |
| **AI Drivability** | Text commands for full automation and testing |
| **Headless Mode** | Simulation runs without graphics for servers/testing |
| **Deterministic** | Fixed seed produces reproducible results |

## 4. Detailed Design

### 4.1 Agent System

#### 4.1.1 Agent Types

| Type | Behavior | Sound Signature |
|------|----------|-----------------|
| **Boid** | Classic flocking (separation, alignment, cohesion) | Contributes to pad volume/layering |
| **Predator** | Pursues nearby boids, causes scatter | Bass drum samples, tension sounds |
| **Attractor** | Stationary or moving point that draws agents | Sustained drone sample |
| **Repulsor** | Pushes agents away | Reversed/dissonant sample |
| **Player** | User/AI controlled agent | Melodic note triggers |

#### 4.1.2 Agent Data Structure

Using mdhavers dicts (not `kin` classes):

```braw
dae make_agent(id, kind, x, y, z) {
    gie {
        "id": id,                    // Unique: "<node>_<counter>"
        "kind": kind,                // "boid", "predator", etc.
        "pos": [x, y, z],            // Position
        "vel": [0.0, 0.0, 0.0],      // Velocity
        "col": [255, 128, 0],        // RGB color
        "energy": 100,               // Lifecycle modifier
        "birth": 0,                  // Tick when spawned
        "sound_cooldown": 0          // Ticks until can trigger sound again
    }
}
```

#### 4.1.3 Agent ID Generation

Format: `<node_id>_<counter>` (e.g., `"local_00042"`, `"node_a_00123"`)

- Node ID is assigned at startup (default: "local")
- Counter increments per spawn
- Guarantees uniqueness across distributed nodes

#### 4.1.4 Behavioral Rules

**Boid Rules (per tick):**
```
1. SEPARATION: Steer away from neighbors within separation_radius
2. ALIGNMENT:  Match average velocity of neighbors within alignment_radius
3. COHESION:   Steer toward center of mass of neighbors within cohesion_radius
4. AVOIDANCE:  Flee from predators within fear_radius
5. BOUNDARY:   Soft boundary steering to keep within world bounds
```

**Rule Parameters (adjustable via commands):**
```
separation_radius  = 2.0
separation_weight  = 1.5
alignment_radius   = 5.0
alignment_weight   = 1.0
cohesion_radius    = 5.0
cohesion_weight    = 1.0
fear_radius        = 10.0
fear_weight        = 3.0
max_speed          = 2.0
max_force          = 0.1
```

### 4.2 Audio System

#### 4.2.1 Audio Architecture

**Constraint:** mdhavers has sample/MIDI playback only, no synthesis API.

**Approach:** Pre-rendered sound library with real-time triggering and modulation.

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Simulation │────►│   Event     │────►│ Quantization│
│  State      │     │  Extractor  │     │   Grid      │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                                               ▼
                                        ┌─────────────┐
                                        │   Sample    │
                                        │   Trigger   │
                                        └─────────────┘
```

#### 4.2.2 Sound Library (Pre-rendered)

| Sample Set | Files | Purpose |
|------------|-------|---------|
| `perc/` | kick.wav, snare.wav, hihat.wav, tom_*.wav | Collision events |
| `bass/` | bass_C.wav, bass_D.wav, ... (per note) | Predator activity |
| `pad/` | pad_major.wav, pad_minor.wav, pad_tension.wav | Ambient density |
| `lead/` | note_C4.wav, note_D4.wav, ... | Player agent melodic |
| `fx/` | whoosh.wav, rise.wav, fall.wav | Birth/death/boundary |

#### 4.2.3 Audio Event Quantization

**Critical:** Events must be quantized to musical grid for coherent output.

```
QUANTIZATION GRID:
- Base tempo: 90 BPM (adjustable 60-120)
- Grid resolution: 1/16th note = 41.67ms at 90 BPM
- Latency budget: 50ms max (allows 1 grid slot lookahead)

QUANTIZATION ALGORITHM:
1. Event fires at simulation time T
2. Calculate next grid slot: slot = ceil(T / grid_interval)
3. Add to pending_events[slot]
4. At each grid slot, trigger all pending events for that slot
```

#### 4.2.4 Sound Mapping with Quantization

| Event | Sound | Quantize | Priority | Cooldown |
|-------|-------|----------|----------|----------|
| **Collision** | perc/kick or snare | 1/16th | Medium | 10 ticks |
| **Predator Attack** | bass/bass_X | 1/8th | High | 30 ticks |
| **Birth** | fx/rise | 1/8th | Low | N/A |
| **Death** | fx/fall | 1/8th | Low | N/A |
| **Boundary Touch** | fx/whoosh | 1/4th | Low | 60 ticks |
| **Density Change** | pad/* | 1 bar | Background | Continuous |

#### 4.2.5 Musical Key and Scale

**Key Modulation Rules (explicit):**

```
KEY SELECTION:
- Default: C major
- Flock coherence > 0.7 → Major key (I, IV, V chords)
- Flock coherence 0.4-0.7 → Add 7ths (Imaj7, IVmaj7)
- Flock coherence < 0.4 → Minor/modal (vi, ii)
- Predator present → Add tension (V7, diminished)

MODULATION TIMING:
- Key changes only at phrase boundaries (every 8 bars)
- Smooth transition: overlap pad samples for 1 bar
```

#### 4.2.6 Voice Limits

| Layer | Max Voices | Stealing Policy |
|-------|------------|-----------------|
| Percussion | 8 | Oldest |
| Bass | 2 | Quietest |
| Pad | 4 | None (crossfade) |
| Lead | 1 | Latest replaces |
| FX | 4 | Oldest |

#### 4.2.7 Spatial Audio

```
PANNING MODEL (stereo):
- pan = (agent.x / world_size) * 2 - 1    // -1 to +1
- For headless: pan data included in event stream

VOLUME ATTENUATION:
- base_volume = 0.8
- distance_factor = 1.0 / (1.0 + distance_from_center * 0.05)
- final_volume = base_volume * distance_factor

MAX AUDIBLE DISTANCE: world_size * 0.8
```

### 4.3 Graphics System

#### 4.3.1 2D Isometric Projection

**Constraint:** mdhavers has 2D raylib only (draw_circle, draw_rect, draw_line).

**Approach:** Isometric projection of 3D simulation onto 2D canvas.

```
ISOMETRIC TRANSFORM:
screen_x = (pos.x - pos.y) * ISO_SCALE + screen_center_x
screen_y = ((pos.x + pos.y) * 0.5 - pos.z) * ISO_SCALE + screen_center_y

Where ISO_SCALE = screen_height / (world_size * 2)
```

#### 4.3.2 Rendering Pipeline

```braw
dae render_frame(world, config) {
    // 1. Clear screen
    screen_clear([20, 20, 30])

    // 2. Draw world boundary (diamond shape in isometric)
    draw_iso_boundary(world.bounds, [50, 50, 60])

    // 3. Sort agents by depth (y + z) for proper overlap
    ken sorted = sort_by(world.agents, |a| a["pos"][1] + a["pos"][2])

    // 4. Draw each agent
    ilk(sorted, |agent| {
        ken screen_pos = iso_project(agent["pos"])
        ken size = get_agent_size(agent["kind"])
        ken color = agent["col"]

        // Agent body (circle)
        draw_circle(screen_pos[0], screen_pos[1], size, color)

        // Velocity indicator (line)
        ken vel_end = iso_project(vec_add(agent["pos"], agent["vel"]))
        draw_line(screen_pos[0], screen_pos[1], vel_end[0], vel_end[1], [255, 255, 255])
    })

    // 5. Draw HUD overlay
    draw_hud(world, config)
}
```

#### 4.3.3 Visual Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `screen_width` | 1280 | Window width |
| `screen_height` | 720 | Window height |
| `world_size` | 50.0 | Cubic world edge length |
| `iso_scale` | auto | Calculated from screen_height/world_size |

#### 4.3.4 Visual Modes

| Mode | Description |
|------|-------------|
| **Standard** | Colored circles with velocity lines |
| **Density** | Heat map overlay (circle alpha = local density) |
| **Velocity** | Color = speed (blue→red gradient) |
| **Type** | Distinct colors per agent type |
| **Minimal** | Dots only (for high agent counts) |

### 4.4 Networking Layer

#### 4.4.1 MVP: Server + Spectators Model

For MVP, networking provides:
- One authoritative server running simulation
- Multiple spectators can connect to watch
- Remote command injection (authenticated)

Distributed simulation is a stretch goal for post-MVP.

#### 4.4.2 Message Protocol

**All messages use JSON with version and sequence numbers:**

```json
{
    "v": 1,
    "seq": 12345,
    "type": "STATE_SYNC",
    "tick": 54321,
    "data": { ... }
}
```

#### 4.4.3 Message Types

| Type | Direction | Protocol | Description |
|------|-----------|----------|-------------|
| `HELLO` | Client→Server | TCP | Join request with role |
| `WELCOME` | Server→Client | TCP | Accept with client_id |
| `STATE_SYNC` | Server→Client | UDP | Periodic state snapshot |
| `COMMAND` | Client→Server | TCP | Control command |
| `RESPONSE` | Server→Client | TCP | Command result |
| `EVENT` | Server→Client | UDP | Audio events for sync |
| `HEARTBEAT` | Bidirectional | UDP | Liveness check |
| `BYE` | Either | TCP | Clean disconnect |

#### 4.4.4 State Sync Protocol

```
STATE_SYNC (UDP, every 100ms):
{
    "v": 1,
    "seq": 54321,
    "type": "STATE_SYNC",
    "tick": 12345,
    "agents": [
        // Compact format: [id, kind_code, x, y, z, vx, vy, vz, r, g, b]
        ["local_42", 0, 10.5, 3.2, 0.0, 1.0, 0.5, 0.0, 255, 128, 0],
        ...
    ],
    "stats": {
        "count": 500,
        "coherence": 0.72
    }
}
```

**Handling out-of-order/dropped UDP:**
- Clients track last received `seq`
- Ignore packets with lower seq (stale)
- Interpolate positions using included velocities for smooth display

#### 4.4.5 Heartbeat and Failure Detection

```
HEARTBEAT_INTERVAL: 1000ms
FAILURE_THRESHOLD: 3 missed heartbeats (3 seconds)

Client sends: {"v":1, "type":"HEARTBEAT", "client_id":"xyz"}
Server responds: {"v":1, "type":"HEARTBEAT_ACK"}

If no heartbeat for 3s:
- Server: Remove client from spectator list
- Client: Show "Disconnected" and attempt reconnect
```

### 5.3 Key Algorithms

#### 5.3.1 Spatial Hashing (Fixed for Negative Coords)

```braw
// Cell size = max of all interaction radii
ken CELL_SIZE = 5.0

dae spatial_key(x, y, z) {
    // Use string keys to handle negative coordinates
    ken cx = floor(x / CELL_SIZE)
    ken cy = floor(y / CELL_SIZE)
    ken cz = floor(z / CELL_SIZE)
    gie f"{cx},{cy},{cz}"
}

dae spatial_insert(spatial, agent) {
    ken key = spatial_key(agent["pos"][0], agent["pos"][1], agent["pos"][2])
    gin spatial[key] == naething {
        spatial[key] = []
    }
    push(spatial[key], agent["id"])
}

dae spatial_query(spatial, pos, radius) {
    ken results = []
    ken cells_to_check = ceil(radius / CELL_SIZE)

    // Check surrounding cells
    fer cx in range(-cells_to_check, cells_to_check + 1) {
        fer cy in range(-cells_to_check, cells_to_check + 1) {
            fer cz in range(-cells_to_check, cells_to_check + 1) {
                ken key = f"{floor(pos[0]/CELL_SIZE) + cx},{floor(pos[1]/CELL_SIZE) + cy},{floor(pos[2]/CELL_SIZE) + cz}"
                gin spatial[key] != naething {
                    results = concat(results, spatial[key])
                }
            }
        }
    }
    gie results
}
```

#### 5.3.2 Agent Update Loop (Fixed Timestep)

```braw
// IMPORTANT: Use fixed timestep for determinism
ken FIXED_DT = 1.0 / 60.0  // 60 Hz

dae update_agents(world) {
    // Rebuild spatial hash each tick
    world["spatial"] = {}
    ilk(world["agents"], |a| spatial_insert(world["spatial"], a))

    // Update each agent
    ken events = []
    ilk(world["agents"], |agent| {
        gin agent["kind"] == "boid" {
            ken neighbors = get_neighbors(world, agent)

            // Calculate steering forces
            ken sep = calculate_separation(agent, neighbors, world["rules"])
            ken ali = calculate_alignment(agent, neighbors, world["rules"])
            ken coh = calculate_cohesion(agent, neighbors, world["rules"])
            ken avoid = calculate_avoidance(agent, world)
            ken bound = calculate_boundary(agent, world["bounds"])

            // Combine forces with weights
            ken force = vec_add(
                vec_scale(sep, world["rules"]["separation_weight"]),
                vec_add(
                    vec_scale(ali, world["rules"]["alignment_weight"]),
                    vec_add(
                        vec_scale(coh, world["rules"]["cohesion_weight"]),
                        vec_add(
                            vec_scale(avoid, world["rules"]["fear_weight"]),
                            bound
                        )
                    )
                )
            )

            // Apply force with FIXED timestep
            force = clamp_magnitude(force, world["rules"]["max_force"])
            agent["vel"] = clamp_magnitude(
                vec_add(agent["vel"], vec_scale(force, FIXED_DT)),
                world["rules"]["max_speed"]
            )
            agent["pos"] = vec_add(agent["pos"], vec_scale(agent["vel"], FIXED_DT))

            // Check for audio events
            events = concat(events, check_audio_events(agent, neighbors, world))
        }
        // ... handle other agent types
    })

    world["tick"] = world["tick"] + 1
    gie events
}
```

│  │ 5. Network  │ broadcast_state(world, spectators)        │
│  └─────────────┘                                           │

```

Scenario: Determinism
> seed 12345
> spawn boid 0 0 0 50
> step 1000
> state local_0
Store position as P1
> reset
> seed 12345
> spawn boid 0 0 0 50
> step 1000
> state local_0
Assert: position == P1
```

### 7.3 Determinism Requirements

With fixed seed and fixed timestep, simulation must be deterministic:
- Same seed → same agent positions at tick N
- Required for: replay, debugging, headless testing, network sync

## 10. Risk Assessment

| Risk | Impact | Mitigation |
|------|--------|------------|
| Performance at 2000+ agents | High | LLVM backend, reduce visual complexity |
| Audio cacophony from too many events | High | Voice limits, cooldowns, quantization |
| Network sync lag | Medium | Velocity-based interpolation on client |
| Complexity of distributed sim | High | **MVP is single-node; distributed is stretch goal** |
