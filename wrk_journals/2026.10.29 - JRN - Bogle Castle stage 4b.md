# Bogle Castle stage 4b: front end and onboarding

Arthur asked for a clear start, menus, restart and door guidance after becoming
stuck in E1M1's courtyard. All changes are local and uncommitted; the lead owns
git. No cargo, runtime/C/Rust implementation, dependency, sound or fleet-board
change was made. The two Rust test harnesses are updated for the new fixtures.

## Cause and change

The old `shell/frame.braw` initialized directly into play and returned false
on Escape. `maps/e1m1.braw:22` places the only courtyard exit in the closed
64-unit-wide gate sector at x384..448, y128..256. Its first two keepers were
beyond the gate. No shell cue told the player to face the gate and press E.

- `shell/frontend.braw:52` owns the deterministic splash/title/play/pause/
  controls/dead/complete/quit state machine. Its inputs are held menu bits,
  gameplay keys, mouse delta and integer frame duration. Menus freeze tics,
  clear pending time/motion, and debounce held keys. Starting/restarting reloads
  pristine map geometry and resets gameplay; Space used to choose cannot also
  fire. Queued mouse rotation is reduced modulo4096 before addition, including
  across frames without a due tic, avoiding overflow at either i64 endpoint.
- `shell/frontend.braw:162` draws the castle splash, game-font menus, Controls,
  elapsed level time on terminal screens, door prompts and an initial gate cue.
  No kills/secrets counters exist, so none were introduced. Completion offers
  Restart/Back to Title because no second level exists.
- `shell/frame.braw:10` retains `bogle_init(w,h)`/`bogle_frame(dt_ms)` and owns
  bridge input, mouse capture, presentation and recording. The native host is
  untouched. Each fresh attempt truncates its recording; only consumed gameplay
  tics are appended. Menus never enter the engine replay.
- `shell/frontend_replay.braw` and `shell/headless.braw` add explicit shell
  replay mode (`BOGLE_FRONTEND=1`); the original engine replay path is retained.
  Shell rows are dt/menu/keys/dx, with screen and pixel hash after each frame.
- `engine/doors.braw:56` extracts the original 64-unit inclusive use trace into
  `bogle_use_sector`, without changing door behavior. `shell/onboarding.braw:4`
  reads that exact target to show E: open / Ye need the iron key / silver key.
  It does not mutate state or change old engine-rendered frames.
- `maps/e1m1.braw:65` relocates one existing keeper from496,160 to300,160,
  facing the first gate. Render subtraction proves1440 visible start pixels at
  320x200. The map still has43 convex sectors and the same pickups/key gates.
- `art/src/title_castle.png` is new Codex imagegen art, opaque320x200,
  114347 bytes. Exact generation/edit prompts and reduced-image review are
  appended in `art/src/PROMPTS.md`. `tools/bake_title.braw` uses the existing
  baker to produce a160x100 column-major palette BOG,16013 bytes. No existing
  art/baker behavior changed.
