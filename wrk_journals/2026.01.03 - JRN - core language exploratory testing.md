## Work log

### `ceilidh` parity fix
- Interpreter behavior: `ceilidh(list1, list2)` interleaves elements; it rejects non-lists (`"ceilidh needs two lists"`).
- LLVM backend previously had a special-case that merged dicts in `ceilidh(dict1, dict2)`, which broke parity and the new golden regression.
- Updated LLVM codegen so `ceilidh`:
  - Type-checks both args are lists.
  - Calls the existing `inline_ceilidh` interleave implementation for list inputs.
  - `hurl`s with `"ceilidh needs two lists"` for any non-list inputs (catchable via `hae_a_bash`).
- Removed the now-unused `inline_dict_merge` helper from `src/llvm/codegen.rs` (dict merging remains available via `dict_merge`).

### `birl` parity + aliasing fix
- Added a golden regression to lock `birl` behavior across backends:
  - `tests/golden/edge_cases/birl_rotation_and_type_errors.braw`
  - `tests/golden/edge_cases/birl_rotation_and_type_errors.expected`
- Issues found (LLVM backend only):
  - No type-checking for `birl` args: wrong types could silently misbehave (or worse, treat non-list data as a list pointer).
  - Returned the original list for `birl([], n)` and `birl(list, 0)`, causing aliasing differences vs the interpreter (which always returns a fresh list).
- Fixes applied (LLVM codegen):
  - `birl` now type-checks `(list, int)` and `hurl`s with interpreter-style messages:
    - `"birl needs a list"`
    - `"birl needs a rotation count"`
  - `inline_birl` now returns a fresh list even when the rotation is a no-op (uses `list_slice` to copy), matching interpreter semantics.
