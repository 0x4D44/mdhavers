# Bogle Castle stage 1: framebuffer bridge

Task: dependency-free macOS native framebuffer/input bridge, matching interpreter names,
integer spinning-gradient demo, and native offscreen validation. No git writes or external writes. All edits remain uncommitted for the lead.
Scratch logs and native smoke executables were removed after recording this evidence.

## Change and backend behaviour

The native codegen previously dispatched graphics calls to placeholders or could not resolve
new framebuffer names. `src/llvm/codegen.rs:24161` now dispatches all 14 bridge names;
`uses_screen` at line 626 flows through object compilation to native linking.
`build.rs:105` builds a separate embedded `mdh_screen.a`; `src/llvm/compiler.rs:456`
adds that archive and the macOS frameworks/libobjc only when codegen saw a bridge call.
Drawing APIs outside this bridge retain their existing Scots hurl.

`runtime/mdh_screen.c:29` checks dimensions/title/open lifecycle; line 63 checks borrowed
pixel/palette types and exact lengths, converts RGB palette indices to BGRA, and supports
raw BGRA. Two owned conversion buffers never retain user bytes. All 14 calls check the
main thread, including `MDH_SCREEN=none`. Offscreen presentation hashes the same converted
bytes with FNV-1a32, emits a numbered stderr line, and keeps input all-up/zero.
`runtime/platform/screen_none.c` supplies the unsupported-platform hurl while common
offscreen mode still works.

`runtime/platform/screen_macos.c` implements AppKit activation/menu/window, runtime delegate
close and Quit detection, manual nonblocking event pumping, key/edge/mouse tables, cursor
grab, nearest-neighbour CALayer presentation, contentsScale from backingScaleFactor, and
autorelease pools. It uses plain C and OS frameworks, with no new dependencies.

`src/graphics.rs:200` adds exact-size indexed/BGRA texture presentation on the existing
raylib window; mouse delta/down/grab are added without changing existing window dimensions
or drawing behaviour. Graphics-off builds now define all 14 bridge names and hurl the
existing Scots error. The interpreter's existing key vocabulary remains unchanged.
JS and WASM code was not changed or newly validated for these bridge names.

`examples/apps/bogle_gradient.braw` supplies demo_init(w,h), demo_frame(dt_ms), and the
section 2.3 host loop. The 320x200 indexed gradient uses only integer ramps/rotation,
arrows change rotation/panning, mouse movement/buttons change a crosshair, G toggles grab,
and Esc returns nae. The native bridge scales the logical framebuffer by four.

## Small choices within the design

- Core Animation can retain CGImages beyond two frames. Each visible image therefore owns
  an immutable BGRA snapshot, freed by its provider callback, in addition to the two reusable
  conversion buffers. This adds one allocation/copy per visible frame and avoids the renderer
  reading a reused/freed buffer. No program-owned pointer survives screen_shaw.
- Indexed alpha is 255. Raw BGRA is hashed byte-for-byte; native presentation ignores alpha
  using the mandated CGImageAlphaNoneSkipFirst. Interpreter presentation also treats that byte
  as padding and forces opaque RGBA.
- Frame numbering starts at 1 and resets on a successful open. Invalid key names hurl.
  Width/height/key/mouse reads require an open screen; close is idempotent, and should_close
  is false with no screen. Fractional raw mouse deltas accumulate until a frame boundary.
- Native opens at x4; the interpreter keeps the existing screen_open size contract.
