# Journal: Nested function scoping (2026-01-05)

## Trigger
While adding a golden parity program for default parameters + closures, the LLVM backend failed to compile when multiple nested functions shared the same source name (`inner`) in different scopes (e.g., inside different functions/methods). The interpreter handles this via lexical environments; LLVM codegen previously treated nested functions as globally-named, which caused collisions and incorrect capture sets.

## Symptom
- `golden_tests_native` failed compiling `tests/golden/functions/default_params_capture_and_param_refs_parity.braw`
  - Error: `Cannot box variable 'x': not found in scope`
  - Diagnosis: the method’s nested `inner` was being resolved to a different `inner` from another scope (capture set included `x`, not `masel`).

## Fix (LLVM backend)
Implemented lexical scoping for nested function *names* in codegen:
- Added `nested_function_scopes: Vec<HashMap<String, String>>` + `nested_function_counter` to `src/llvm/codegen.rs`.
- Nested functions are now declared with unique internal symbols via `next_nested_function_symbol` (e.g., `__mdh_nested_<outer>_<name>_<id>`), and the current scope maps `source_name -> internal_name`.
- Name resolution for function calls / function-as-value now consults the scope stack first:
  - `CodeGen::compile_expr` (function-as-value path)
  - `CodeGen::compile_call` (direct call path)
  - `CodeGen::compile_stmt` (nested function body compilation)
- Ensured scopes are pushed/popped correctly for:
  - `compile_function`
  - `compile_method_body`

## Regressions found + fixed during implementation
- Scope stack leak: `compile_function` was pushing twice and popping once; fixed to push exactly once.
- Method scope: `compile_method_body` initially popped without pushing; fixed to push a scope so nested-method functions resolve correctly.
- Coverage guardrails regressed due to new closure instantiations; refactored a few `unwrap_or_else`/`map_err` closure sites into `match`/`if let` to keep `scripts/coverage_guardrails.sh` at 100% functions + instantiations.
- Updated `tests/llvm_codegen_missing_lines_coverage.rs` for new semantics:
  - calling a method-local nested function (`outer`) at top-level now correctly yields `Undefined variable: outer`.

## Bug found: defaults must evaluate in callee closure env (LLVM)
Interpreter evaluates default expressions in the **callee's closure environment** (not the caller's),
so caller locals should not affect defaults for global functions.

Repro (native mismatch):
- `tests/golden/functions/defaults_use_callee_closure_not_call_site_scope.braw`
  - interpreter: `f()` returns global `g` (1)
  - native (before fix): `f()` returned caller-local `g` (2)

Fix:
- `src/llvm/codegen.rs`
  - `compile_user_function_call`: while compiling default expressions, temporarily filter
    `self.variables` to only captured vars + temporarily bound params (then restore).
  - `call_function_value`: apply the same filtering for both simple function and closure dispatch
    when compiling default expressions.

Validation:
- `timeout 600 cargo test --test golden_tests golden_tests_interpreter` ✅
- `timeout 900 cargo test --test golden_tests golden_tests_native --features llvm` ✅
- `timeout 2400 bash scripts/coverage_guardrails.sh` ✅

## Bug found: variable binding must shadow built-ins (LLVM)
While adding a program that stores a function value in a variable named `get`, native compilation failed with:
- `CompileError("dict_get expects 3 arguments")`

Root cause:
- In `compile_call`, any call where the callee is a `Variable` named `"get"` was treated as the builtin `dict_get` alias, even if a local/global variable binding existed with that name (interpreter semantics: locals shadow globals/builtins).

Fix:
- In `src/llvm/codegen.rs`, `compile_call` now checks `self.variables`/`self.globals` first; if a binding exists, it compiles the callee as a first-class function value and dispatches via `call_function_value` (before builtin/function/class fast paths).

- `timeout 900 cargo test --test golden_tests golden_tests_native --features llvm` ✅
