# 2026.01.04 - JRN - llvm class values

## Context
- Core-language parity gap (interpreter vs LLVM/native):
  - Interpreter treats `kin` definitions as first-class values:
    - `ken C = Box` works
    - `C(41)` constructs an instance and runs `init` (if present)
  - LLVM backend previously rejected `Box` as a value with `CompileError("Undefined variable: Box")`.

## Work done
### Implemented: classes as first-class values (LLVM)
- `src/llvm/codegen.rs`
  - Added `make_class(...)` (tag = `ValueTag::Class`, data = ptr-to-int of the class name global).
  - `compile_expr` (`Expr::Variable`) now supports class identifiers as values:
    - Returns a `Class` value when `name` is in `self.classes` and is not hidden.
    - Preserves existing runtime “defined before use” guards via `class_defined_flags`.
  - `call_function_value(...)` now supports calling `Class` values:
    - Dispatches by the stored class-name pointer and instantiates the matching class.

### Regression fixed: module verification failure from class-dispatch IR
- The initial `Class` support in `call_function_value(...)` generated instantiation blocks for *all* classes at a call site.
- If a class’s `init` arity didn’t match the call-site argument count, the IR would contain invalid calls (wrong arg count) and LLVM verification would fail (seen in `golden_tests_native`).
- Fix: class instantiation now truncates supplied args to the `init` method’s expected user-arg count, ensuring the generated `init` call always matches the declared signature.
  - Note: this preserves compilation correctness, but currently **ignores extra args** instead of raising a “wrong arity” runtime error (possible future parity improvement).

## Tests added
- `tests/llvm_class_values.rs`
  - `ken C = Box; C(41)` works and returns a usable instance.
  - Class values round-trip through dicts and remain callable.
- `src/llvm/codegen.rs` unit tests:
  - Added a small coverage-only test to ensure `make_class(...)` runs in the unit-test crate instance (prevents coverage regression).
