# Bogle Castle stage 5: sound

Arthur requested sound with an OS-only PCM bridge and all synthesis/mixing in
mdhavers. No git writes, commits, integration, new dependencies or external posts.

## Implementation

- `runtime/mdh_sound.c`: bounded 1 MiB copied PCM ring, mono/stereo signed16 LE at
  22050/44100 Hz; main-thread API and locked AudioQueue callback; roughly 5 ms
  device buffers. Queued counts scalar samples, including in-flight output.
- `build.rs`, `src/llvm/{codegen,compiler,ownership}.rs`: separate embedded sound
  archive, call dispatch, conditional AudioToolbox link and borrowed ownership rows.
- `src/graphics.rs`: deterministic null sound per interpreter, with matching
  validation/capacity and no graphics/audio dependency requirement.
- `games/bogle/audio/mixer.braw`: twelve bounded integer procedural voices with
  per-voice seeded noise, finite envelopes, clipping and a sustained bagpipe drone.
- `games/bogle/engine/{game,weapons,things,ai,doors}.braw`: tic result event lists;
  no new simulation inputs, clocks, audio bridge calls or randomness. The pure
  front end aggregates events; the native shell targets 1323 queued mono samples
  (60 ms), stops the drone outside play and closes sound on exit.
- `games/bogle/README.md`: API, synthesized cues, null backends and playback notes.

## Backend behavior

Before this stage, LLVM and the interpreter had no `sound_*` names and Bogle
emitted no sound cues. Native macOS now implements the PCM device API; the
interpreter and non-macOS native builds expose deterministic null sound.
JavaScript and WASM gain no sound host API in this stage. Headless rendering
retains its existing behavior and committed hashes. Panning/distance attenuation
remain outside this implementation; the mixer output is mono.

  rejects `sound_*` calls in pure engine/front-end sources.

## Manual playback limitation

The game native entry built successfully and a short real run reached
`sound_open`, then reported `couldnae open the audio device`. An independent
minimal AudioQueue probe returned OSStatus -66680, which the local SDK names
`kAudioQueueErr_InvalidDevice`. This session cannot verify a real output stream
or listening. Null playback and callback behavior are device-free checks, not
proof of audible playback. The built game executable was removed after the run.
