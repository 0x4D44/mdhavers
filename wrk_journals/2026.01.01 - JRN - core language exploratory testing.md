## Update - Casing + char-class parity (ASCII-only, UTF-8 safe)
- Closed a remaining interpreter/native mismatch in case conversion + character classification:
  - Interpreter now uses ASCII-only (UTF-8 safe) semantics for:
    - `upper` / `lower` (`to_ascii_uppercase` / `to_ascii_lowercase`)
    - `capitalize` (uppercases first byte if ASCII)
    - `title` (preserves whitespace; ASCII-only word casing)
    - `swapcase` (ASCII-only byte transform)
    - `is_alpha` / `is_space` (ASCII-only byte classes)
    - `is_upper` / `is_lower` (“Python-style”: ignores non-letters, requires at least one ASCII letter).
  - Native runtime now matches + is locale-safe:
    - `__mdh_title_case` throws on non-string and uses ASCII-only transforms (no `toupper`/`tolower`).
    - `__mdh_is_space` now checks multi-character strings correctly and throws on non-string.
    - `__mdh_capitalize` / `__mdh_swapcase` are ASCII-only and UTF-8 safe.
    - `__mdh_reverse_str` now delegates to `__mdh_slice_string(..., step=-1)` so it’s Unicode-safe (codepoint reversal) and throws on non-string.
  - LLVM codegen now avoids segfaults and matches semantics:
    - `inline_is_char_class` updated so `is_upper` / `is_lower` ignore non-letters and require at least one ASCII letter.
    - `is_upper` / `is_lower` / `is_alpha` / `is_digit` / `is_alnum` now type-check for string inputs before calling `strlen` (type errors are catchable; prevents pointer crashes).
  - Added golden regression test: `tests/golden/edge_cases/case_charclass_title_whitespace_parity.*`.
