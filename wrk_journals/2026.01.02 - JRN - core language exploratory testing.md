### 2026-01-02 — Dict/Creel aliasing + nested update parity (native handle-based storage)
**Problem found (native vs interpreter mismatch)**
- Interpreter dicts/creels behave like **mutable reference types** (aliases see updates; nested updates like `l[0]["x"] = 1` work).
- Native backend had **partially persistent** behavior:
  - updating an existing key could mutate in place (aliases saw it),
  - inserting a new key reallocated and only updated the immediate binding (aliases and nested containers did *not* see it),
  - nested updates like `l[0]["y"] = 2` could be “lost” because codegen couldn’t store back to the list element.

**Decision**
- Standardize on the interpreter (and JS compiler) semantics: **dicts and creels are mutable reference-like values**; updates must be visible through aliases and nested containers.

**Implementation**
- Runtime (`runtime/mdh_runtime.c`):
  - Dict/creel `Value.data` now points to a **stable handle** that stores a pointer to the payload.
  - Mutating ops (`dict_set`, `toss_in`, `heave_oot`) update the handle to point at a resized payload as needed.
  - All dict/creel readers (`len`, `to_string`/JSON, `keys`/`values`, set ops like `creels_*`, `blether_format`, etc.) now dereference the handle to reach the payload.
- LLVM backend (`src/llvm/codegen.rs`):
  - Dict literals now allocate payload + handle and return a dict whose data is the handle pointer.
  - Dict indexing / dict-merge fastpaths / `len(dict|creel)` / `is_toom(dict)` / truthiness for sets now load the payload pointer from the handle before reading `[count][entries...]`.

**Tests**
- Added golden regressions:
  - `tests/golden/edge_cases/dict_aliasing_and_nested_updates.*`
  - `tests/golden/edge_cases/set_aliasing_and_nested_updates.*`

### 2026-01-02 — LLVM list index assignment: add runtime type checks + bounds checks (catchable)
**Problem found**
- LLVM backend list index assignment (`l[i] = v`) performed a direct store with no bounds checks.
  - Out-of-range indices could write past the list buffer (memory corruption / crash) instead of throwing a catchable error.

- Added bounds checks for list index assignment in both the slow path and the fast path; out-of-bounds now `hurl`s `"Hoachin'! Index is oot o' bounds"` (catchable via `hae_a_bash`).
