# Bogle Castle, stage 5b

The engine is a pure integer portal renderer. Positions and heights in game state
use signed 16.16 integers; map coordinates are integer units. Angles cover one
turn in 4096 steps, with zero east and 1024 north. The committed sine table is
generated by `python3 games/bogle/tools/gen_trig.py`; projection needs no tangent
or arctangent table. Walls use perspective-correct texture columns and 16.16 vertical steps. Floors
and ceilings sample world texels per column. The fixed palette has 32 baked
light maps with sector and distance shading. Sprites face the player, sort far
to near, and clip against the screen and portal drawsegs; index 255 is transparent.
The tartan ghost and the cylindrical sky are full bright.

Run from the repository root with `MDHAVERS_HOME` pointing there:

```sh
mdhavers run games/bogle/shell/headless.braw
mdhavers build games/bogle/shell/native.braw -o .scratch/bogle
.scratch/bogle
```

Startup shows the castle splash with **Press ony key**, then the title menu:
**New Game**, **Controls**, **Kit List**, **Quit**. Navigate menus with Up/Down or W/S and
choose with Enter/Space. Escape during play opens **Resume**, **Restart Level**,
**Controls**, **Kit List**, **Quit**; Escape also resumes or returns from Controls or the Kit List. Menus
freeze the simulation and release the mouse. Resume captures it again. Held
menu keys must be released before they can fire or choose another item.

WASD moves, the mouse and Left/Right arrows turn, E uses doors and the exit,
Space or left mouse fires, and 1–4 select owned weapons. Hold fire for at
least 21 tics with the bagpipes, then release to blast; holding 35 tics fires
automatically. Controls are also available from the title and pause menus.
Death offers **Restart** and **Back to Title**. Completing the Gatehouse offers
the same choices: there is no next level yet. Both screens show elapsed level
time from the existing 35 Hz tic count; kills and secrets are not tracked.

E1M1 starts in the courtyard facing a visible gamekeeper. Follow the courtyard
east to the gate; face the door within 64 units and **E: open** appears. Locked
doors name the missing iron or silver key. Moving gates have portcullis faces;
the iron-key gallery door uses the cell-door face, so the two keyed doors also
look different. Faces are assigned to both room-side portal walls when doors
are initialized, preserving explicitly authored wall textures. Use/key prompts
are centered above the crosshair and highest weapon tip at 320x200.
The gatehouse, hall, kitchen, crypt,
chapel and battlement exit remain reachable.

The shell exposes `bogle_init(w,h)` and `bogle_frame(dt_ms)` in
`shell/frame.braw`; the native host still owns the tiny loop. The bridge-free
`shell/frontend.braw` state machine accepts explicit held menu bits and gameplay
input, advances an exact 35 Hz accumulator with at most four tics per frame,
and draws each screen in the game font. Menu time and mouse motion are discarded
on transitions. Native windowed play is a manual acceptance check.

The native headless executable accepts `<map> <replay> <w> <h> <every>`. The
interpreter CLI accepts only a script filename, so both backends also accept
`BOGLE_MAP`, `BOGLE_REPLAY`, `BOGLE_W`, `BOGLE_H`, and `BOGLE_EVERY`. Defaults are
the test map, `replays/stage2.txt`, 80, 50, and 35. Each replay row contains a key
bitmask and mouse delta. Bits are forward 1, back 2, left strafe 4, right strafe
8, turn left 16, turn right 32, fire 64, use 128, and weapon selections
256/512/1024/2048. Positive mouse delta turns right. Each hash row
is a one-based tic followed by unsigned decimal FNV-1a of the indexed bytes.
The final tic is hashed even when it falls between sampling intervals.
`BOGLE_LIMIT` caps a replay prefix; `BOGLE_REQUIRE_EXIT=1` asserts completion
alive with both keys and all four weapons.

Native `--record games/bogle/replays/name.txt` or `BOGLE_RECORD` records inputs
actually consumed by tics. Mouse deltas accumulate between tics and are consumed
once, including frames with several due tics. Starting a new game or restarting
truncates the recording so it always contains one uninterrupted level attempt;
menu frames never enter the gameplay recording.

`tools/mapbuild.braw` provides `new_map`, `room`, `split_convex`, `door`, `stairs`,
`map_thing`, `validate`, and `write`. The design's `thing(...)` spelling cannot
be a function name: `thing` is a reserved struct keyword. `map_thing` performs
that operation without changing the language. `tools/testmap.braw` rebuilds
`data/test.map`; run `mdhavers run games/bogle/tools/replaybuild.braw` from the
repository root to rebuild the 350-tic input route. The route visits all eleven
convex sectors and crosses every portal, including all four stairs and the joins
generated from the L-shaped room.

BOGMAP 1 records follow design section 4.5. Texture ids 0..9 select granite,
flagstone moss, slate underside, dungeon brick, oak panel, thistle tapestry,
Celtic lintel, cell door, portcullis and peat straw. IDs 10..14 add bog, chapel
stone, fryer oil, exit lever and loch water. Other accepted IDs use granite.
Ceiling texture -1 means sky. Sector kinds are normal 0, door 1, fryer 2,
bog 3 and cold water 4. Door tags 0/1/2 mean unlocked/iron/silver. Thing type 1
is the player start; 2..5 select gamekeeper, haggis, tartan ghost and midges.
Types 10..20 are oatcake, haggis plate, juice can, juice bottle, shortbread, Mars
box, powder, blunderbuss, bagpipes, iron key and silver key. Type 21 is the exit;
30..36 are stag head, armour, brazier, thistle, cow portrait, banner and curling
stone. Wall flag bit 1 blocks. Doors move their ceilings and wait for bodies
to clear before closing. Loader
validation pairs exact geometric reversed edges, rejects partial or repeated
edges, enforces convex CCW polygons and reachability, and locates the player.

Tests (from the repository root):

```sh
cargo test --no-default-features --features cli,llvm,native \
  --test bogle_unit --test bogle_parity --test bogle_bridge -- --test-threads 3
```

`bogle_unit` runs every `games/bogle/tests/*.braw` fixture on the interpreter and
the native compiler and compares it with its `.expected` file, and scans
`engine/` for floats, bridge, clock and random names. `bogle_parity` replays
`replays/stage2.txt` at 80x50 on the interpreter and on native builds with
reference counting off and on, and compares each with `replays/stage2.hashes`.
It also runs the two-frame `stage3` room replay in all three modes, and the
30-frame `frontend` replay through splash, title, Controls, play, pause, resume
and restart. `BOGLE_FRONTEND=1 BOGLE_MAP=games/bogle/data/e1m1.map
BOGLE_REPLAY=games/bogle/replays/frontend.txt` selects shell replay mode in
`headless.braw`; each row is `dt_ms menu_bits gameplay_keys mouse_dx` and each
output row is frame number, screen and frame hash. Menu bits are Up=1, Down=2,
Choose=4, Escape=8, Any Key=16. The existing two-column engine replay format
and its frame hashes are unchanged.
The 671-tic `e1m1.txt` playthrough runs in full natively with RC off/on; its
first 140 tics run on the debug interpreter. Five frame hashes include the
exit overlay. `bagpipes_replay.braw` separately asserts the recorded blast
disperses midges and stuns and pushes a gamekeeper. A deliberate
rendering change re-blesses hashes only after all three outputs agree. Stage 3
changes the stage 2 hashes because baked wall/flat texels, sky columns and fixed
palette light maps replace the synthetic flat colour ramps. Geometry regression
fixtures inject constant textures and retain their existing exact pixel assertions.
The game renderer's WASM deployment is stage 8; binary I/O already uses the WASM host.

The baker runs entirely in mdhavers, with no runtime tool dependencies:

```sh
mdhavers build games/bogle/tools/bake_all.braw -o .scratch/bake
.scratch/bake
mdhavers run games/bogle/tools/stage3map.braw
mdhavers build games/bogle/tools/stage3frame.braw -o .scratch/frame
.scratch/frame
```

The last command renders the room with a step, rear gamekeeper and foreground
haggis, reports a native 320x200 frame time in nanoseconds and writes
`.scratch/bogle-stage3.ppm`. Clock and filesystem output remain in tools/.
`stage3map.braw` rebuilds the room with the normal map builder.

`tools/png.braw` decodes eight-bit gray, RGB, indexed and RGBA PNGs. It implements
stored, fixed and dynamic deflate, checks Adler-32, reverses all five filters,
and rejects interlacing. PNG chunk CRC is outside the selected subset. Fixture
creation and exact output are documented in `tests/png/README.md`.

`tools/bake.braw` is a library; `bake_all.braw` writes the asset manifest and the
colormap. It box-filters textures to 64x64 with periodic sampling, fits cropped
sprite content in 64x96 with visible feet on row 95, fits weapon frames in
128x96, and resizes sky to 256x128.
Alpha below 128 or RGB within 24 per channel of magenta masks a source pixel.
Sprites, weapons and HUD faces additionally mask magenta dominance (red and blue at least
128 and each at least 64 above green), removing antialiased purple fringes.
Textures and sky retain their original predicate so natural purple stays opaque.
A filtered texel is opaque at 50% foreground coverage; foreground RGB alone is
averaged and quantised to the nearest palette index 0..254 (lowest index wins ties).
BOG files have `BOG1 width height\n` headers and column-major payloads. Colormap
columns are levels (`BOG1 32 256\n`), indexed `level*256+colour`; each level scales
RGB by `(32-level)/32` before nearest-palette lookup. Transparent 255 stays 255.
Real granite and gamekeeper fixtures rebake and compare complete committed bytes.
Run the baker natively for bulk art; interpreter rebake fixtures use the harness's
existing 300-second per-process ceiling on a loaded shared box.

Rebuild E1M1 with `mdhavers run games/bogle/maps/e1m1.braw`. Its 43 convex
sectors cover the courtyard, gatehouse, hall and dais, kitchen, eight descending
steps, crypt, gallery, chapel and battlements. The iron key opens the gallery;
the silver key opens the battlement stair. The kitchen offers Mars bars, the
chapel holds bagpipes, and the final lever ends the level. Bog and fryer floors
hurt; bog and cold water slow movement. The kelpie, bogle, Piper’s Ghost, caber and whisky barrels
remain deferred as specified by the design.

`tools/stage4frame.braw` replays to the descending stair near the crypt, renders
an enemy and key with the held weapon, measures ten warm native 320x200 renders,
and writes `.scratch/bogle-stage4.ppm`. Randomness is the seeded Park–Miller
state in the pure engine; the shell alone handles input, clocks and recording.

`new_game(map)` recognizes gameplay things (types 10 and above). The optional
`new_game(map, aye)` enables gameplay for focused maps with only doors or
enemies; earlier renderer-only test maps retain their static geometry.

The new title illustration is generated with Codex imagegen; exact prompts and
review notes are in `art/src/PROMPTS.md`. Its source is an opaque 320x200 PNG;
`tools/bake_title.braw` uses the shared baker to produce the 160x100 indexed
`data/title_castle.bog` (16,013 bytes). The shell scales it with nearest sampling.
Run `tools/frontend_shots.braw` after creating `.scratch/shots/` to reproduce
320x200 PPM captures of splash, title, pause, Controls, start, door prompt, death
and level completion. `gate_start` looks at the closed courtyard gate from the
player start; `door_iron` and `door_silver` show the distinct keyed doors and
missing-key prompts.

Sound is synthesized and mixed in `audio/mixer.braw`: mono signed 16-bit
little-endian PCM at 22050 Hz, with twelve bounded voices, integer envelopes,
seeded noise and clipping. Slot zero sustains the bagpipe drone while filling;
release gives a blast or a sad deflate. Other procedural cues cover the sgian-dubh
swish, Mars throw/splat, blunderbuss, door grind, pickup chime, gamekeeper shout,
haggis fuse/explosion, ghost wail, midge buzz, player oof and menu blips. There
are no audio sample files or new dependencies. Effects are mono, without
positional panning or distance attenuation.

`tic` returns a fresh list of sound event names; the pure front end collects
all due tics' events for its host. These outputs do not affect simulation or
rendering. The native shell fills to 1323 queued samples (60 ms) each frame;
three approximately 5 ms AudioQueue buffers account for the device's extra
buffering. Pausing stops the drone, resuming a charged bag restores it, and a
new run resets mixer voices. The existing headless and replay hosts import no
audio bridge and retain their committed frame hashes.

The OS-only native bridge provides `sound_open(rate, channels)`,
`sound_queue(bytes)`, `sound_queued()` and `sound_close()`. It accepts 22050 or
44100 Hz and one or two channels. Queue input must contain complete signed16
little-endian interleaved frames; the bridge copies borrowed bytes before
returning. `sound_queued()` counts **scalar samples**, including samples already
in device buffers: stereo frames count twice. The capacity is 1 MiB (524288
scalar samples). Close is idempotent and clears the queue; queued returns zero
when closed. Device calls must run on the main thread; AudioQueue's callback
only copies the locked C ring and never enters mdhavers. Only programs using
the sound names link AudioToolbox.

`MDH_SOUND=none` or `MDH_SCREEN=none` selects a deterministic null bridge that
counts samples without draining them or opening a device. The game shell skips
audio initialization under either flag. On other native platforms and in the
interpreter, the API currently uses null sound; interpreter state belongs to
each interpreter instance. Native macOS reports an error if a real output
device cannot open. Arthur's listening check needs a logged-in session with an
available Core Audio output device.

`tests/audio.braw` hashes every timbre and checks sustain/stop, chunk independence,
finite tails, voice bounds and clipping. `tests/sound_events.braw` checks engine
and menu events. The Rust bridge gate also exercises lifecycle, input validation,
null backends, thread restrictions, framework isolation, and a device-free C
callback harness for borrowed copies, ring wrapping, in-flight counts and
underrun silence.


Stage 5b adds an illustrated **Kit List** to the title and pause menus. Its ten
pages show all four weapons, all eleven pickups and the four enemy kinds, using
the same baked sprites seen in play. Up/W goes back a page; Down/S or Enter/Space
advances; Escape returns to the menu. The simulation stays frozen while reading.
Weapon 1 is the **sgian-dubh** (quick melee, no ammunition); the selection bits
and recorded replay format are unchanged.

Pickups gently bob two units above and below their spawn height and briefly brighten on a repeating
integer tic schedule. Their messages explain health, spirit, ammunition, weapon
unlocks and the key's door. Girder Juice in a can restores **15** health; the
bottle fills health and doubles speed for three seconds. The cow portrait,
tartan banner and stag head are scenery hung beside walls with centres at eye
height. The cow now hangs on the courtyard's south wall near the start. Armour,
braziers, thistle pots and curling stones block movement like furniture. The
banner is scenery; the separate bagpipe pickup unlocks weapon 4.

The enlarged HUD has a status face: health above 75/50/25/0 selects fine/hurt/
bad/dire, and zero health selects dead. Damage briefly shows ouch; weapon and key
pickups show a grin. The healthy face occasionally glances left or right on a
fixed tic schedule. These events and pickup motion use game tics only. A keeper
shakes his fists for 35 tics on first sight before charging; subsequent windups
retain their original 18 tics. The fist pictures alternate every five tics.

Run `tools/bake_polish.braw` through a native build to bake available status-face
and gamekeeper-fist sources. HUD faces use 32x32 indexed data and fists use the
usual 64x96 sprite data. Missing art uses an explicit FACE placeholder or the
existing keeper attack picture. The source art is maintained separately.
`tools/polish_shots.braw` writes review PPMs to `.scratch/shots5b/`, including all
Kit List pages, the HUD, courtyard dressing/pickup bob and both fist phases.
